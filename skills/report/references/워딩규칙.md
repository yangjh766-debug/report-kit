# 워딩 규칙 (한국어 업무 문서)

AI가 쓴 한국어 문서가 "AI가 쓴 티"가 나지 않게, 그리고 숫자 사고가 나지 않게 지키는 규칙이다.
보고서, 메일, 메모, 투자자 자료 어디에나 쓴다. 회사마다 다른 용어는 맨 아래 「회사별 용어」에 따로 적는다.

이 파일은 두 군데서 쓰인다.
- report 스킬이 문서를 쓸 때 읽는다.
- wording 스킬이 코덱스에게 문장 다듬기를 맡길 때 함께 보낸다. 이때 **「## 코덱스에게 전달할 규칙」 절의 `- ` 줄만** 전달되므로, 그 절에는 규칙만 두고 작업 메모를 섞지 않는다.

---

## 1. 숫자와 사실

1. 원본에 없는 숫자, 사실은 만들지 않는다. 모르면 `[확인 필요: 무엇]`으로 둔다. 값 자리만 비면 `##`.
2. 문서 안 모든 숫자는 근거(파일, 쪽, 셀)를 댈 수 있어야 한다. 작업 원고에는 `(출처: 파일 p.N)`을 붙이고, 남에게 보내는 최종본에서는 뗀다.
3. 금액은 한국식 단위로 쓴다. `95.9m`, `1.6bn` 금지. `95,868,891원`, `9,587만원`, `16억원`(억원은 소수 둘째 자리까지).
4. 숫자에는 단위를 붙인다. 표에는 `(단위: 백만원)` 줄을 둔다.
5. 매출, 원가 등 금액은 부가세 제외(공급가액)로 쓴다. 부가세 포함 원천(영수증, POS, 소비자가)은 1.1로 나눠 쓰고 표 단위 줄에 `(부가세 제외)`를 적는다. *(재무 문서에 해당)*
6. 반올림은 사사오입. 파이썬 `round()`는 짝수 쪽으로 반올림하므로 쓰지 않는다(`Decimal ROUND_HALF_UP`).

## 2. AI 티가 나는 표현 (금지)

| 쓰지 않는 것 | 대신 |
|---|---|
| 가운뎃점 나열 「제작·운영」, 「티켓·MD」 | 「제작과 운영」, 「티켓, MD」, 「A 및 B」 |
| 가운뎃점 조어 「매입·판매형 사업」 | 문장으로 풀어 쓴다 |
| 「A가 아니라 B」 문형 반복 | 그냥 B라고 말한다 |
| 화살표(→)로 문장 잇기 | 「~하여 ~하였습니다」 |
| 줄표(—)로 덧붙이는 설명 | 쉼표나 별도 문장 |
| 「주목할 점은」, 「핵심은」, 「결론적으로」 같은 머리말 | 바로 내용 |
| 근거 없는 최상급: 최고, 유일, 압도적, 혁신적, 획기적, 세계적 | 사실과 수치만 |
| 단정 미래 「~할 것입니다」 | 「~할 계획입니다」, 「~로 예상됩니다」 |
| 개조식 「~함」, 「~임」, 「~음」 (보고 문장에서) | 「~습니다」, 「~입니다」 |
| 영어 단위, 영어 섞어 쓰기 「YoY +12%」 | 「전년 대비 12% 증가」 |
| 딱딱한 직역투 「이식」, 「막는다」, 「차단」 | 「옮기기」, 「공유」, 「멈춘다」, 「걸러낸다」 |

내보내기 전에 `grep -c "·" 파일`이 0건인지 확인한다. 코덱스 워딩 결과에도 다시 들어올 수 있으니 워딩 뒤 한 번 더 본다.

## 3. 쓰지 않는 문장

- 작업 과정 설명: 「결산자료로 작성하였습니다」, 「~을 기준으로 작성하였습니다」, 「원장에서 역산」, 「대조하였습니다」. 작업 과정은 검증 파일에만 남긴다.
- 반올림 해명: 「천원 미만 반올림으로 합계와 차이가 날 수 있습니다」. 합은 표 안에서 맞춘다.
- 이미 한 일을 미래형으로: 「신청할 예정」이 아니라 「신청하였습니다」.
- 표가 없는 자리의 「다음과 같습니다」.

## 4. 문체

- 같은 어미가 세 문장 이상 이어지지 않게 한다.
- 「또한」, 「특히」, 「이러한」으로 시작하는 문장을 연달아 쓰지 않는다.
- 주어(「당사는」)는 한 문단에 한두 번만. 뒤 문장은 주어를 생략하거나 「이를 통해」, 「이에 따라」, 「아울러」로 잇는다.
- 문장을 짧게만 끊지 않는다. 원인과 결과는 「~하였으며, ~」로 한 문장에 잇고, 한 문장이 세 줄을 넘으면 나눈다. 한 문단 3~5문장.
- 회사가 준 설명문은 사실(날짜, 금액, 상대방, 인과, 시제, 확신의 정도)을 그대로 두고 문체만 바꾼다. 「회복 중」을 「회복될 것으로 예상됩니다」로 바꾸면 없는 전망을 만든 것이다.

## 5. 표식과 형광

| 상황 | 표식 | docx에서 |
|---|---|---|
| 값만 없음 | `##` (날짜 `##.##`) | 노란 형광 |
| 무엇이 없는지 밝혀야 함 | `[확인 필요: ○○]` 짧게 | 노란 형광 |
| 사용자가 채울 공란 | `[○○○]`, `[ ]` | 노란 형광 |
| 사실 의심, 검토 의견 | `[메모: …]` | Word 메모 |

사용자가 손대야 하는 곳은 반드시 노란색이다. 공란을 놓친 채 계약서가 나가는 사고를 막는다.

## 6. 외부로 나가는 파일

- 엑셀은 사람이 만든 것처럼: Arial 9, 머리글 회색(D9D9D9) 검정 굵게, 소계 연회색(F2F2F2), 회계 숫자서식(`_-* #,##0_-`), 제목은 `[제목]`. 노랑, 파랑 같은 강조색과 긴 설명 주석은 넣지 않는다.
- 내부 검증 시트, 확인 메모는 제출 파일에서 떼어 `…_내부확인.xlsx`로 따로 둔다.
- 제출용 Word, 엑셀 안에 출처 표기, 파일명, 쪽수, 시트명을 남기지 않는다.
- 주민번호, 개인 휴대전화, 개인 계좌번호는 옮기지 않고 책임자에게 알린다.

## 코덱스에게 전달할 규칙

- 숫자, 날짜, 금액, 비율, 고유명사는 한 글자도 바꾸지 않는다.
- [확인 필요: …], (출처: …), ##, [메모: …] 표식은 글자 하나 바꾸지 말고 같은 자리에 둔다.
- 서술식 경어체("~습니다", "~입니다")로 쓴다. "~함", "~임" 같은 개조식은 쓰지 않는다.
- 가운뎃점(·)으로 단어를 나열하거나 붙이지 않는다. 쉼표, "및", "와/과"로 쓴다.
- "A가 아니라 B" 문형, 화살표(→), 줄표(—)로 문장을 잇지 않는다.
- 최고, 유일, 압도적, 혁신적, 획기적, 세계적 같은 근거 없는 최상급을 쓰지 않는다.
- 미래는 "~할 계획입니다", "~할 예정입니다", "~로 전망됩니다"로 쓰고 "~할 것입니다"로 단정하지 않는다.
- 같은 어미가 세 문장 이상 이어지지 않게 한다. "또한", "특히", "이러한"으로 시작하는 문장을 연달아 쓰지 않는다.
- 원인과 결과는 한 문장으로 잇고, 한 문장이 세 줄을 넘으면 나눈다. 짧게 끊긴 번역투 문장을 만들지 않는다.
- 원문에 없는 원인, 평가, 전망을 보태지 않는다. 시제와 확신의 정도는 원문 그대로 둔다.
- 표를 소개하는 "~는 다음과 같습니다." 문장을 새로 만들지 않는다.
- 작업 과정 설명(결산자료로 작성, 기준으로 작성, 반올림 차이)을 새로 쓰지 않는다.
- 금액을 m, bn 같은 영어 단위로 바꾸지 않는다.
- "이식", "막는다", "차단" 같은 딱딱한 직역투 대신 "옮기기", "공유", "멈춘다", "걸러낸다"처럼 평범한 말을 쓴다.
