# 10. 증권신고서 투자위험요소 작성

상장예비심사를 통과한 뒤 금융감독원에 내는 증권신고서(지분증권) 「투자위험요소」(사업위험, 회사위험, 기타위험)를 쓰는 방법이다. 한 번의 실제 작업에서 정한 방식을 회사 정보 없이 옮겼다. 신청서 작성 규칙(02~09 문서)은 여기에도 그대로 적용하고, 이 문서는 신고서에서 달라지는 것만 다룬다.

---

## 1. 목표와 기본 태도

- **정정요구를 받지 않는 것**이 목표다. 금감원은 「청약자가 이 회사의 위험을 판단할 만큼 충분히 적었는가」를 본다.
- 숫자는 하나도 틀리지 않는다. 그중 **재무제표 숫자와 주식 숫자**는 절대 틀리면 안 된다. 그래서 이 작업에서 가장 중요한 것은 검증이다.
- 위험을 줄여 말하지 않는다. 회사 대응은 사실만 짧게 쓰고, 장점 홍보는 넣지 않는다.
- 공개 수위는 신청서에 적은 수준과 같게 한다. 고객사 실명, 고객별 비중, 단가, 마진을 신청서보다 더 공개하지 않는다.

## 2. 착수 때 사용자에게 한 번에 물을 것 (질문서)

질문서를 먼저 만들어 답을 받고, 답을 결정사항 표(번호, 항목, 결정, 근거)로 지침에 적는다. 사용자가 답하지 않은 항목은 추천안을 적용하고 「추천안 적용」이라고 표시해 두며, 바꾸라고 하면 바로 바꾼다.

| 번호 | 항목 | 물을 것 |
|---|---|---|
| 1 | 기준일 | 재무 기준일(최근 반기 등), 주식은 작성일 현재인지. 다음 분기 검토보고서가 나오면 롤포워드할지 |
| 2 | 범위 | 사업, 회사, 기타위험 모두인지. 기타위험은 관용 문장 틀 + 회사 사실로 쓸지 |
| 3 | 연결, 별도 | 신청서 지침의 연결별도기준을 그대로 따를지 |
| 4 | 참고 대상회사 선정 순서 | 업종을 먼저 볼지, 시기를 먼저 볼지. 상장 유형(기술특례 등) 가산 여부 |
| 5 | 몇 개사 | 정독 대상(문단 구조까지 참고, 3~5사)과 빈도 분석 대상(위험 목록만, 10~15사) |
| 6 | 넣거나 뺄 회사 | 꼭 참고할 회사, **참고하지 말아야 할 회사**(문체 기준으로도 쓰지 않을 회사) |
| 7 | 공시 모음 자료 접근 | 공개 공시를 모아 둔 자료(트래커 등)가 있으면 받는 방법. 잠겨 있으면 접근 권한자에게서 비밀번호를 받는다(3절) |
| 8 | 기본 태도 | 보수적으로 충분히 적을지 |
| 9 | 위험 하나의 구성 | 4절 구성을 쓸지 |
| 10 | 핵심 위험 후보 | 신청서에서 먼저 본 후보 목록. 빼거나 더할 것, 조심스럽게 다룰 것 |
| 11 | 예심 지적사항 | 거래소, 주관사가 예심 중 물은 것의 위치. 금감원도 볼 가능성이 크다 |
| 12 | 공개 수위 | 고객 실명, 비중, 단가를 어디까지 |
| 13 | 다른 부분 참조 문구 | 신고서 안의 다른 부분 참조(「'제2부 Ⅱ. 사업의 내용'을 참고하시기 바랍니다」)는 관행이라 허용할지. 신청서 참조는 금지 |
| 14 | 재무 숫자 원천 순서 | 감사, 검토보고서 PDF → 정산표(차이 0 확인) → 신청서 작업 원본은 교차 확인용 |
| 15 | 주식 숫자 원천 | 신청서 제출본 숫자를 출발점으로 할지, 공모 숫자는 주관사 최신 공모 구조표로 할지 |
| 16 | 업종 평균 | 신청서 재무분석과 같은 업종 분류, 연도를 쓸지 |
| 17 | 문체 기준 문서 | 어느 신고서의 문장 틀을 기준으로 삼을지(대표주관회사가 최근 주관한 신고서가 무난) |
| 18 | AI 문장 도구에 맡길 범위 | 7절 「중간」 방식으로 할지 |
| 19 | 결과 형식 | 공시 화면 모양 HTML, 제출용과 검증용 두 벌 |
| 20 | 사용자 확인 시점 | 대상회사 확정, 위험 목록 확정, 첫 위험 2개 작성 뒤 |

## 3. 보안과 외부 자료

- 결과는 공시 시스템(DART 등) 작성기가 아니라 HTML로 만든다. 프로젝트 폴더 안에만 두고 외부에 게시하지 않는다.
- **잠긴 외부 자료의 비밀번호는 접근 권한이 있는 사람만 쓰게 한다.** 비밀번호는 매번 사용자에게 받고, 지침, 스킬, 메모, 스크립트, 산출물, 보고 어디에도 적지 않는다. 복호화 스크립트는 비밀번호를 실행할 때 입력받게 만든다(파일에 박지 않는다). 비밀번호가 바뀌어도 같은 방식이다.
- 웹은 공개 공시와 공개 통계만 읽는다. 검색어에 회사 내부 숫자를 넣지 않는다.
- 내려받은 공시 원문은 새 빈 폴더에 두고, 그 파일을 읽는 파이썬은 `python3 -I`로 실행한다.

## 4. 단계

| 단계 | 하는 일 | 사용자 확인 |
|---|---|---|
| 1. 참고 대상회사 선정 | 후보 전체 점수(업종, 시기 가중, 상장 유형 가산, 고객 구조 유사성) → 정독 대상, 빈도 분석 대상. 정정요구 교훈 목록 | 끝에서 |
| 2. 위험 선정 | 기재 요령 체크리스트 + 참고회사 빈도 + 회사 고유 사실로 위험 목록과 순서 | 끝에서 |
| 3. 위험 작성 | 숫자 원장 → 재료표 → 골격 → AI 문장 → 숫자 채움 → HTML. 핵심 위험 2개 먼저 | 첫 2개에서 문체 확인 |
| 4. 검토 | 독립 검증, 금감원 시각 검토, 숫자 반대 검증, 직접 전수 확인 | 최종 |

- 정독 대상은 **최종 효력본** 기준으로 본다. 마지막 정정이 비교표뿐이면 직전 전문 정정본에 그 정정을 반영한다.
- **정정요구 사례는 학습 자료다.** 「금감원이 무엇을 더 쓰라고 했나」를 유형별로 뽑아(접수번호를 단다) 우리 초안에 처음부터 넣는다. 자주 나오는 보강 요구: 최근 가결산 실적, 추정 실적의 근거, 비교기업 선정 근거, 수주 현황, 자금 사용 일정, 희석을 반영한 유통가능물량.
- 사용자가 참고하지 말라고 한 회사는 정독, 빈도 분석, 문체 기준 어디에도 넣지 않는다. 산출물에 그 회사가 들어가지 않았는지 검사한다.

## 5. 위험 하나의 구성과 평가 기준

**구성**
1. 제목: 「가. ○○에 따른 위험」. 참고회사의 같은 위험 제목 표현을 따른다.
2. 요약 박스: 3~5문장, 핵심 숫자 1~3개, 「투자자께서는 이 점 유의하시기 바랍니다.」로 맺는다.
3. 현황: 산업 또는 회사 현황. 외부 숫자는 기관명, 발간 시점과 함께.
4. 표: 위험을 보여 주는 숫자 표. 표 제목 위, 단위 오른쪽 위, 주) 표 바로 아래.
5. 현실화 경로: 무엇이 일어나면 → 당사의 어느 숫자가 → 어떻게 나빠지는가.
6. 회사 대응: 사실만, 위험 분량보다 짧게. 계획은 「~할 계획입니다」.
7. 맺음: 투자자 유의 문구. 한 위험 안에서 요약 박스 끝과 본문 마지막에만 둔다.

분량은 위험의 무게에 따라 나눈다. 회사 고유의 핵심 위험은 표 2~4개, 기타위험의 정형 항목(공모가 하회, 수요예측, 효력발생의 의미 등)은 관용 문장 틀 그대로 짧게.

**평가 기준(하나라도 못 미치면 그 위험은 통과시키지 않는다)**

| 기준 | 통과 | 반려 |
|---|---|---|
| 구체성 | 회사의 숫자, 사실(금액, 비중, 추세, 거래처 수, 기간)로 위험을 보인다 | 업종 일반론만. 다른 회사 이름만 바꿔 넣어도 성립하는 문단 |
| 현실화 경로 | 사건 → 숫자 → 악화가 이어진다 | 「영향을 미칠 수 있습니다」로만 끝난다 |
| 균형 | 대응은 사실만, 짧게 | 위험을 상쇄하는 홍보, 「위험은 제한적」 같은 단정 |
| 최신성 | 기준일 숫자와 작성일 현재 사실(가결산, 수주, 소송 진행) | 예심 신청 때 숫자를 그대로 둔다 |
| 정합성 | 신고서의 다른 부분(사업의 내용, 재무, 공모 개요)과 숫자, 표현이 같다 | 같은 숫자가 부분마다 다르다 |

## 6. 숫자 원장과 숫자 쓰는 법

- 본문, 표, 요약 박스의 숫자는 직접 쓰지 않고 **숫자 원장의 번호**로만 쓴다(예: `⟦N0123⟧`). 값은 조립 스크립트가 채운다. 번호 없이 들어간 숫자는 그 자체로 오류다.
- 증감률, 비중, 배수 같은 파생 숫자도 원장에서 산식으로 만든다. 사람이나 AI가 계산해 적지 않는다. 산식은 쉬운 함수만(02 문서 4.3절).
- 원장 열: 번호(한 번 준 번호는 바꾸지 않음), 등급, 항목, 값, 단위와 표시, 원천 파일, 위치(쪽, 시트!셀), 산식, 교차 확인(신청서의 같은 숫자와 일치 여부).
- 이미 검증을 마친 신청서 대조표의 행을 끌어와도 되지만, 그 행의 원천까지 함께 적는다. 원장 값은 따로 만든 재계산 스크립트로 원천에서 다시 읽어 차이 0을 확인한다.
- 표의 기간 순서는 신고서 관행(대표주관회사 신고서)을 따른다. 최근 기간을 왼쪽에 두는 신고서가 많아 신청서(최근을 오른쪽)와 다를 수 있다. 업종평균 열은 맨 오른쪽. 어느 쪽으로 했는지 지침에 적는다.
- 본문 속 음수는 「영업손실 ○○백만원」처럼 말로 풀고 절댓값을 쓴다. 표 안 음수는 괄호.
- 반올림 차이 설명 문구를 쓰지 않는다. 표 안에서 합계를 맞춘다.

**숫자 등급별 검사**

| 등급 | 대상 | 검사 |
|---|---|---|
| A재무 | 재무제표, 주석 숫자와 그 파생 | 전수. 감사(검토)보고서 PDF ↔ 정산표 ↔ 신청서 작업 원본 3자 대조. PDF 원문을 직접 연다 |
| A주식 | 발행주식수, 공모주식수, 지분율, 주식매수선택권, 의무보유, 유통가능물량, 희석 | 전수 + 내부 정합: 공모 전 주식수 + 신주 = 공모 후 주식수, 지분율 합 100%, 의무보유 + 유통가능 = 상장예정주식수 |
| B회사 | 고객별 매출, 수주, 인원, 특허 등 | 전수 원천 대조 |
| C외부 | 시장 규모, 업황, 경제 전망 | 기관명, 발간 시점 필수. 원문을 열어 숫자 확인 |

## 7. 문장: 골격은 직접, 문단 완성은 AI 문장 도구 (「중간」 방식)

신고서는 위험 문단이 길고 논리가 중요해서, 신청서처럼 「초안 → 다듬기」로 하지 않고 일을 나눈다.
1. **재료표:** 위험마다 사실 목록(근거 번호 `⟦R01⟧`), 쓸 숫자 번호, 표 설계, 논리 순서, 참고 문단의 구조 요약.
2. **골격:** 문단마다 요지 1~2문장, 숫자는 번호, 근거는 근거 번호. 문장은 거칠어도 된다.
3. **문단 완성:** AI 문장 도구(wording 스킬 등)에 골격과 신고서용 문체 규칙을 넘긴다. 표식(⟦⟧, `[확인 필요]`)은 글자 하나 바뀌면 안 된다. 분량은 늘어도 된다.
4. **대조:** 결과의 표식 집합이 골격과 같은지 스크립트로 대조한다. 하나라도 다르면 그 조각은 버리고 다시 돌린다. 결과의 숫자 표식을 손으로 고치지 않는다(유의 문구 중복 같은 문장 삭제만 허용).
5. 표, 표 제목, 단위 줄, 주)는 AI에게 보내지 않고 원문을 유지한다.

**신고서용 문체 규칙 만들기:** 문체 기준으로 정한 신고서(참고하지 말라고 한 회사는 제외)에서 **문장 틀만** 뽑아 `지침/증권신고서/워딩규칙_신고서.md`로 만든다. 회사명, 숫자는 옮기지 않는다. 자주 쓰는 틀:
- 「당사의 ○○비율은 20X1년 ○%, 20X2년 ○%, 20X3년 ○%로서, ~에 따라 ~하였습니다」로 연도별 숫자를 나열한 뒤 원인을 잇는다.
- 업종평균과의 비교는 「업종평균 ○% 대비 열위(양호)한 수준」.
- 위험은 「~할 경우 ~할 수 있습니다」, 「~에 부정적인 영향을 미칠 수 있습니다」. 「~할 것입니다」로 단정하지 않는다.
- 끝은 「그럼에도 불구하고 ~할 경우 ~ 수 있습니다. 투자자께서는 이 점 유의하시기 바랍니다.」
- 「위험은 제한적입니다」, 「해소되었습니다」처럼 위험을 줄여 말하는 표현을 새로 만들지 않는다. 최상급(최고, 유일, 압도적, 혁신적, 획기적) 금지.
- 다른 회사 이름, 신청서 쪽수와 참조, 작업 과정(「대조하였습니다」, 「원장 기준」)은 쓰지 않는다.

참고회사 문단은 구조와 문장 틀만 본다. 내용, 숫자, 고유명사는 옮기지 않는다. 기타위험의 관용 문장은 틀을 그대로 쓰되 회사 사실로 바꾼다.

## 8. 서브에이전트에게 일을 나눌 때

- 단계마다 지시서 틀을 지침에 두고, 단계에 맞는 입력과 산출물만 채워 쓴다. 비용과 품질 때문에 모델을 명시한다.
- 공통 머리말에 넣을 것: 맡은 단계와 회사 개요(업종 수준), 먼저 읽을 지침, 금지(원본자료 수정, 파일 삭제, 커밋과 push, 회사 자료를 외부로 보내는 일, 참고 금지 회사 자료 사용, 숫자 추정), 웹은 공개 자료만, 모르는 것은 `[확인 필요]`와 「확인필요」 시트, 마지막 보고에 만든 파일 경로와 행 수, 스스로 확인하지 못한 것.
- 결과는 요약 문장이 아니라 정해진 형식의 파일(xlsx, json)로 낸다. 모든 항목에 원천 위치(파일, 쪽, 시트, 셀 또는 공시 접수번호)가 있어야 한다.
- **쓴 쪽이 자기 결과를 검증하지 않는다.** 검증 담당에게는 결과물과 원천만 주고 작성자의 판단 과정은 주지 않는다. 숫자 원장 담당과 작성 담당도 나눈다.
- 2단계에서는 1단계 결과를 보지 않은 담당이 신청서만 읽고 위험 목록을 따로 만들게 해, 두 목록의 차이를 하나씩 판정한다.
- 서브에이전트의 「완료했다」는 보고를 믿지 않는다. 산출 파일과 스크립트를 직접 다시 돌려 판정한다.

## 9. 단계별 검증과 통과 기준

**1단계**: 접수번호마다 공시에서 회사명, 보고서명, 제출일 확인. 선정 점수표를 다시 계산하고, 상위 회사가 빠졌으면 제외 사유가 있어야 한다. 참고 금지 회사가 없는지. 정정요구 교훈의 항목마다 원문 위치가 있는지 표본 확인.

**2단계**: 금감원 기재 요령의 검토 항목마다 어느 위험에 들어갔는지(해당 없으면 사유 한 줄). 빈도 분석 대상 3사 이상에 공통인 위험이 빠졌으면 사유. 회사 고유 사실(자본잠식 이력, 우선주 전환, 관계회사, 계류 소송, 차입과 보증, 주식매수선택권, 상장주선인 지분 등)이 모두 어느 위험과 연결되는지.

**3단계**: HTML의 숫자를 전부 뽑아 원장 번호와 1:1로 이어지는지(연도, 조항 번호처럼 숫자가 아닌 숫자는 사유를 적은 허용 목록으로). 사실 문장마다 근거 번호가 있고 그 근거가 문장을 실제로 뒷받침하는지 문장 단위 판정. 참고회사 원문과 문장 겹침률(관용 문장 허용 목록 제외). 금지어 0건: 타사명, 참고 금지 회사, 원천 수정 표현, 호칭, 개인정보, 신청서 참조 문구, 반올림 차이 설명.

**4단계**: 금감원 심사역 역할 담당이 5절 기준으로 위험마다 통과, 반려와 사유. 숫자 반대 검증 담당은 틀린 숫자를 찾는 일만 한다. 마지막으로 A등급은 전수로 원천 PDF를 직접 열어 확인하고 B, C는 표본. 결과를 검증기록(날짜, 단계, 검사, 건수, 조치)에 남긴 뒤 사용자에게 넘긴다.

| 검사 | 통과 기준 |
|---|---|
| 원장 재계산 차이 | 0건 |
| 번호 없는 숫자 | 0건 |
| A주식 내부 정합 | 0건 |
| AI 문장 전후 표식 차이 | 0건 |
| 금지어 | 0건 |
| 근거 없는 사실 문장 | 0건 |
| 금감원 시각 반려 | 0건(남으면 사유와 함께 사용자에게 보고) |

## 10. 결과 HTML

- 공시 화면과 비슷하게: 큰 제목(1. 사업위험), 위험 제목(가.), 요약 박스(테두리 한 칸), 표(머리행 회색, 숫자 오른쪽 정렬).
- 제출용은 원천 표기, 근거 번호가 없다. 검증용은 숫자에 마우스를 올리면 원장 번호, 원천 파일, 쪽, 셀이 보인다.
- 위험별 파일과 합본 하나. 외부 글꼴, 스크립트를 불러오지 않는 단일 파일. 외부 게시 금지.
