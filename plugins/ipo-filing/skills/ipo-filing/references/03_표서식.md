# 03. 표 서식

신청서 표를 어떤 틀로 그리고, Word(docx)에서 어떤 모양으로 마무리하는지 정한 문서다. 회사 이름, 숫자, 사람은 들어 있지 않다. 예시의 「㈜○○」, 「최대주주 A」, 「1,234,567」, 「YY.MM.DD」는 모두 가상이다.

숫자가 맞는지 검증하는 규칙은 이 문서의 범위가 아니다. 여기서는 숫자가 이미 검증되었다고 보고, 그 숫자를 어떤 모양으로 보여 줄지만 다룬다.

---

## 1. 이 문서를 언제 쓰나

- 마크다운 초안에 표를 처음 그릴 때: 「가. 표의 틀」부터 읽는다.
- 초안을 docx로 바꾼 뒤, 또는 사용자나 회사가 고친 작업본 docx의 표를 손볼 때: 「나」~「바」를 적용한다.
- 임원, 주주, 자본금 표를 만들 때: 「사. 표 종류별 규칙」도 함께 본다.
- 장을 넘기기 전: 「5. 작업 끝 점검표」를 한 줄씩 확인한다.

**우선순위.** 표의 열 구성은 「거래소 양식 → 과거 신청서」 순으로 정한다. 색, 정렬, 글자 크기 같은 서식은 「그 회사 사용자가 새로 정한 규칙 → 이 문서 → 양식의 기본 서식」 순으로 따른다. 사용자가 새로 정한 규칙은 지침 파일에 날짜와 함께 적어 둔다.

---

## 2. 규칙

### 가. 표의 틀

**규칙 1. 열 구성은 양식에서 찾고, 없으면 과거 신청서에서 찾아 그대로 따른다.**
이유: 심사역은 양식 틀에 익숙하다. 가진 자료에 맞춰 표를 그리면 빠진 정보가 눈에 띄지 않는다.
- 표를 그리기 전에 양식 docx에서 같은 표의 열 이름, 열 순서, 행 이름(직급 행, 소계, 합계 등), 병합 모양을 뽑아 본다.
- 양식에 없는 표는 같은 업종 과거 신청서 2~3건에서 같은 절의 표를 찾아 열 단위로 비교하고, 공통 구성을 쓴다.
- 비교 결과는 대조표 엑셀의 「표_대조」 시트에 남긴다. 열은 「우리 표 | 양식 표 | 과거 신청서 | 채택」이다.
- 열을 임의로 없애지 않는다. 자료가 없는 칸은 「-」이나 `[확인 필요: …]`로 둔다.
- 꼭 열을 더해야 하면 맨 오른쪽 「비고」 바로 앞에 넣는다.

**규칙 2. 해당 사항이 없으면 빈 표를 두지 않는다.**
이유: 빈 표는 누락처럼 보인다. 과거 신청서도 모두 한 문장으로 갈음한다.
- 표 전체가 해당 없으면 `당사는 상장예비심사신청서 제출일 현재 해당사항이 없습니다.` 한 문장으로 쓴다.
- 표 안의 일부 항목만 해당 없으면 그 칸에 「해당사항 없음」이라고 쓴다.

**규칙 3. 표 앞뒤의 부속 요소를 갖춘다.**
이유: 양식의 표 단위 구성이 이렇다. 독자가 단위와 기준일을 표 밖에서 찾지 않아도 된다.
- 표 앞에 안내 문장 한 줄을 둔다. 예: `당사의 최근 3개 사업연도 매출실적은 다음과 같습니다.`
- 표 제목은 `[표 제목]`처럼 대괄호로 쓰고, 굵게, 가운데 정렬한다.
- 단위는 표 오른쪽 위에 `(단위: 천원)`, 9pt, 오른쪽 정렬로 쓴다. 단위가 둘이면 `(단위: 주, %)`로 쓴다.
- 기준일이 필요하면 단위와 같은 줄 왼쪽에 `(YYYY.MM.DD 현재)`로 쓴다.

**규칙 4. 연도 열은 오래된 연도부터 최근 연도 순으로 왼쪽에서 오른쪽에 둔다.**
이유: 양식 기재요령이 이 순서다. 최근 연도가 맨 오른쪽이다.
- 머리글은 `YYYY년(제N기)` 형식이고, 반기는 `YYYY년 반기(제N기 반기)`로 쓴다.

**규칙 5. 표가 너무 넓으면 의미 단위로 둘로 나눈다.**
이유: 열이 15개를 넘으면 숫자가 칸을 넘치고, 글자를 줄여도 읽기 어렵다.
- 예: 차입금 명세를 「명세」 표와 「상환계획」 표로, 10년치 표를 5년씩 두 표로, 월별 명세를 상반기와 하반기로 나눈다.

**규칙 6. 같은 정보가 되풀이되면 칸을 합친다.**
이유: 같은 글자가 줄마다 반복되면 표가 무거워지고 정보의 묶음이 보이지 않는다.
- 세로 병합: 위아래 칸 값이 같고, 그 왼쪽 열들도 같은 범위로 병합되어 있을 때만 합친다. 숫자, 「-」, 빈칸은 같아도 합치지 않는다.
- 가로 병합: 한 행이 여러 칸을 차지하는 줄(보수 총액 줄, 합계 행의 이름 칸 등)은 가로로 합친다.
- 가로 병합 칸은 아래 「라. 열 폭」의 폭 계산에서 뺀다.

**규칙 7. 합계 행과 소계 행은 굵게 쓰고, 이름은 「합계」, 「소계」로 통일한다.**
이유: 양식과 과거 신청서가 모두 이렇게 쓴다. 이름이 표마다 다르면 검토자가 헷갈린다.

**규칙 8. 표 너비는 본문 폭의 100%로 하고, 레이아웃은 고정으로 둔다. 테두리는 모두 가는 단일 실선이다.**
이유: 표마다 너비가 다르면 문서가 들쭉날쭉하다. 고정 레이아웃이어야 Word가 열 폭을 멋대로 바꾸지 않는다.

### 나. 머리행, 글꼴, 줄간격

**규칙 9. 머리행은 회색 음영 `D9D9D9`, 굵게, 가로 가운데와 세로 가운데로 맞춘다.**
이유: 거래소 양식 원본의 색이다. 표마다 머리행 모양이 같아야 본문과 머리글이 한눈에 구분된다.
- 2단 머리행도 머리행이다. 예: 위 행 「소유주식수(지분율)」 아래 「기초 | 증가 | 감소 | 기말」.
- 2단 머리행은 위 행에서 같은 글자가 이어지는 칸을 가로로 합치고, 아래 행에 따로 쓸 말이 없는 칸(「성명」, 「구분」 등)은 위 칸과 세로로 합친다.
- docx에서 머리행을 기계로 판정할 때는 맨 위 행부터 내려가면서 「모든 칸이 회색이거나 위 칸과 세로 병합으로 이어진 칸」이고 「회색 칸이 하나 이상」인 행까지를 머리행으로 본다.

**규칙 10. 글꼴은 맑은 고딕, 표의 기본 크기는 9pt, 본문은 10pt다. 한 표 안의 글자 크기는 모두 같게 한다.**
이유: 한 칸만 작은 글자가 섞이면 실수로 보인다.
- 다른 칸과 크기가 다른 칸이 있으면 그 표의 기본 크기로 맞춘다.

**규칙 11. 표 칸과 본문 모두 줄간격 1.0, 문단 앞뒤 간격 0으로 둔다.**
이유: 줄간격이 크면 행 높이가 커져서 한 쪽에 들어가는 행이 줄고, 칸마다 간격이 달라 보인다.

### 다. 정렬

**규칙 12. 정렬은 열 단위로 통일한다. 숫자는 오른쪽, 날짜와 짧은 글은 가운데, 긴 글은 왼쪽이다.**
이유: 한 열 안에서 정렬이 섞이면 표가 지저분해 보인다. 접히는 글을 가운데 정렬하면 줄마다 시작 위치가 달라 읽기 어렵다.

칸 하나의 종류는 아래 순서로 판정한다. **날짜를 숫자보다 먼저 본다.** `YYYY.MM.DD`는 숫자처럼 생겨서 순서를 바꾸면 날짜가 오른쪽으로 붙는다.

| 순서 | 종류 | 판정 기준 |
|---|---|---|
| 0 | 판정 제외 | 빈칸, 「-」, `##`, `##.##`, `[확인 필요: …]` |
| 1 | 날짜 | `YYYY.MM`, `YYYY.MM.DD`, `YY.MM.DD`, 일부가 `##`인 날짜, `날짜~날짜`, `날짜~현재` |
| 2 | 숫자 | 쉼표 숫자, 소수, 괄호 음수, 단위가 붙은 수(`%`, `원`, `주`, `명`, `년`, `개`, `배`), `1,234(12.34%)` 꼴 |
| 3 | 짧은 글 | 줄마다 길이가 50단위 이하(한글 2단위, 영문과 숫자 1단위)이고 3줄 이하 |
| 4 | 긴 글 | 그 밖의 글(약력, 변동 원인, 내용 설명 등) |

열의 정렬은 그 열 본문 칸들의 종류를 모아 정한다.
- 숫자만 있는 열은 오른쪽이다.
- 긴 글이 하나라도 있는 열은 왼쪽이다.
- 그 밖의 열(날짜, 짧은 글, 날짜와 짧은 글이 섞인 열)은 가운데다.
- 가로 병합 칸은 열을 따르지 않고 자기 내용으로 정한다. 긴 글이면 왼쪽, 아니면 가운데다.
- 본문 칸은 모두 세로 가운데로 둔다.
- 본문 안에 회색 칸(왼쪽 구분 열 등)이 있으면 긴 글이 아닌 한 가운데로 둔다.

판정용 정규식 예시(파이썬):

```python
import re
PEND = re.compile(r"^(##(\.##)?|\[확인 필요[^\]]*\])$")
D1   = r"(\d{4}\.(\d{2}|##)(\.(\d{2}|##))?|\d{2}\.\d{2}\.(\d{2}|##))"
DATE = re.compile(r"^" + D1 + r"(~(" + D1 + r"|현재))?$")
NUM  = re.compile(r"^[\(\-]?\d[\d,]*(\.\d+)?\)?(%|원|주|명|년|개|배)?(\(\d[\d.,]*%\))?$")

def units(s):                      # 한글 2, 영문과 숫자 1
    return sum(2 if ord(c) > 0x2E7F else 1 for c in s)

def kind(text):                    # text: 칸 안 글자, 줄은 \n으로 구분
    s = text.strip()
    if s in ("", "-") or PEND.match(s):
        return None                # 판정 제외
    if DATE.match(s):
        return "date"              # 날짜를 숫자보다 먼저
    if NUM.match(s.replace(" ", "")):
        return "num"
    lines = s.split("\n")
    if len(lines) <= 3 and all(units(x) <= 50 for x in lines):
        return "short"
    return "long"

def column_align(kinds):           # kinds: 그 열 본문 칸들의 kind 집합(None 제외)
    if kinds and kinds <= {"num"}:
        return "right"
    if "long" in kinds:
        return "left"
    return "center"
```

### 라. 열 폭과 칸 안 줄바꿈

**규칙 13. 열 폭은 균등하게 나누지 않고, 맑은 고딕의 실제 글자 폭을 재서 정한다.**
이유: 글자 수로 어림하면 한글과 숫자의 폭 차이 때문에 숫자가 잘리거나 짧은 이름이 접힌다.

절차:
1. 글자 폭을 잰다. 맑은 고딕 글꼴 파일은 Word 설치 폴더의 `malgun.ttf`(굵게는 `malgunbd.ttf`)를 쓴다. 맥에서는 `/Applications/Microsoft Word.app/Contents/Resources/DFonts/`에 있고, 윈도에서는 `C:\Windows\Fonts\`에 있다.
2. 열마다 「최소 폭」을 구한다. 숫자, 날짜, 괄호 묶음(「(최대주주)」 등), 6자 이하의 짧은 글은 통째로 한 줄에 들어가야 한다. 그 밖의 글은 띄어쓰기와 여는 괄호 「(」 앞에서 끊을 수 있다고 보고, 끊고 남은 가장 긴 조각이 들어가는 폭을 최소 폭으로 잡는다. 머리행 글자도 똑같이 잰다(굵게).
3. 열마다 「한 줄 폭」을 구한다. 그 열에서 가장 긴 줄이 한 줄에 들어가는 폭이다.
4. 모든 열의 한 줄 폭 합이 표 너비 안에 들어가면 그대로 쓰고, 남는 폭은 긴 글 열에 나눠 준다.
5. 들어가지 않으면 모든 열에 최소 폭을 먼저 주고, 남는 폭은 줄바꿈이 생기는 긴 글 열에 몰아준다. 여럿이면 폭을 줬을 때 표 전체 줄 수가 가장 많이 줄어드는 열부터 준다.
6. 표 전체 너비와 고정 레이아웃은 바꾸지 않는다. 열 폭의 합이 표 너비와 같아야 한다.
7. 가로 병합 칸은 폭 계산에서 뺀다. `[확인 필요: …]` 칸은 「[확인 필요]」 폭만 보장한다. 확인 뒤 없어질 글이라 접혀도 된다.
8. 사용자가 직접 정한 열 폭이 있으면 그 값을 기준으로 쓰고, 쪼갤 수 없는 것(숫자, 괄호 묶음)이 안 들어갈 때만 넓힌다.

글자 폭 재기 예시(파이썬, Pillow 필요). 폭 단위는 Word의 dxa(1/20pt)다.

```python
from PIL import ImageFont
FD = "/Applications/Microsoft Word.app/Contents/Resources/DFonts/"   # 윈도: C:/Windows/Fonts/
FR = ImageFont.truetype(FD + "malgun.ttf", 1000)
FB = ImageFont.truetype(FD + "malgunbd.ttf", 1000)
MARGIN = 57 * 2                    # 셀 좌우 여백(각 57dxa, 약 1mm)

def text_dxa(s, pt=9, bold=False):
    # 1.03배와 20dxa는 Word와의 측정 오차 여유
    return (FB if bold else FR).getlength(s) / 1000 * pt * 20 * 1.03 + 20

def cell_need(lines, pt=9, bold=False):   # 칸 안 줄 목록이 각자 한 줄에 들어가는 폭
    return max(text_dxa(x, pt, bold) for x in lines) + MARGIN
```

**규칙 14. 칸 안 줄바꿈은 의미 단위로 문단을 나눠서 한다.**
이유: Word의 자동 줄바꿈에 맡기면 낱말이나 숫자 중간에서 잘린다. 한 줄에 의미 하나가 다 담겨야 읽힌다.
- 예: 「상환전환 / 우선주」, 「대표이사 / (등기)」, 「사임 / (YY.MM.DD)」, 「유상증자 / (출자전환)」, 「본인 / (최대주주)」. 「/」 자리에서 칸 안 문단을 나눈다.
- 숫자, 날짜, 괄호 묶음은 한 줄에 둔다.
- 낱말 하나가 칸보다 길면 의미 경계에서 나눈다. 예: 「기타 / 비상무 / 이사(등기)」.
- 이미 나눈 줄이 있으면 그 줄을 경계로 존중한다.
- 정보가 많은 칸(약력 등)은 항목마다 줄을 바꾼다.

**규칙 15. 글자 크기는 최후의 수단이다. 폭이 모자라면 아래 순서로 해결한다.**
이유: 신청서는 읽히는 것이 먼저다. 「잘 보이게 해 달라」는 요청에 글자를 줄이는 것은 정반대 행동이다.
1. 열 폭 재배분: 짧은 열을 줄이고 긴 열에 몰아준다(규칙 13).
2. 표 안에서 줄이기: 날짜의 「20」 생략(규칙 18), 비고의 긴 글을 주)로 옮기기(규칙 23), 반복 칸 병합(규칙 6).
3. 의미 단위 줄바꿈(규칙 14).
4. 셀 좌우 여백을 108dxa에서 57dxa로 줄이고, 줄간격을 1.0으로 맞춘다.
5. 그래도 숫자가 잘릴 때만 0.5pt씩 줄인다. 하한은 6.5pt다. 줄인 표는 사용자에게 어느 표를 몇 pt로 줄였는지 보고한다.
- 원래 크기보다 작아지게 하지 않는다. 예전에 자동으로 줄어 있던 표를 만나면 먼저 기본 크기(9pt)로 되돌리고 1~4번으로 다시 맞춘다.
- 긴 글 열의 줄 수가 늘어나는 것은 글자를 줄일 이유가 아니다.

### 마. 표 안 표기

**규칙 16. 숫자는 쉼표, 괄호 음수, 소수 둘째 자리로 쓴다.**
이유: 과거 신청서의 일관된 관행이다. 표기 방식이 섞이면 검토자가 오류로 본다.
- 천 단위 쉼표: `1,234,567`.
- 음수: `(1,234)`. 「△」나 「-1,234」는 쓰지 않는다.
- 비율과 지분율: `12.34%`. 배수와 회전율: `1.23배`, `4.56회`.
- 금액 단위: 재무제표와 계정 명세는 천원, 양식이 백만원으로 정한 요약표는 백만원, 공모 관련은 원.
- 주식수: `1,234,567주`, 액면가: `500원`.

**규칙 17. 표 안의 0은 「-」로 쓴다.**
이유: 과거 신청서의 관행이다. 0이 많으면 의미 있는 숫자가 묻힌다.

**규칙 18. 날짜는 표 안에서 `YYYY.MM.DD`, 본문에서 `YYYY년 MM월 DD일`로 쓴다. 9열 이상 표에서는 「20」을 생략해 `YY.MM.DD`로 쓴다.**
이유: 열이 많은 표에서 「20」 두 글자를 줄이면 날짜 열이 좁아져 다른 열에 폭이 돌아간다.
- 월과 일은 두 자리로 쓴다(`YYYY.01.05`).
- 「20」 생략은 칸 내용이 날짜뿐일 때만 한다. 기간(`YY.MM.DD~YY.MM.DD`)은 양쪽 모두 생략한다.
- 열 수는 병합 전 표 격자의 열 수로 센다.
- 한 표 안에서는 한 가지 형식만 쓴다.

**규칙 19. 가운뎃점(·)을 쓰지 않는다. 쉼표나 「및」으로 바꾼다.**
이유: 사용자가 정한 문체 규칙이다. 가운뎃점은 검색과 문장 다듬기에서 잘 깨지고 읽는 사람마다 뜻을 다르게 받는다.
- 둘이면 「A 및 B」 또는 「A, B」, 셋 이상이면 「A, B, C」로 쓴다.
- 예외: 법령명, 양식 제목, 정관이나 규정 조문을 그대로 인용한 표, 「」 안의 인용, 「소재·부품·장비」, 「유·무형」처럼 그 표기가 고유 명칭인 것.

**규칙 20. 대기 표식은 노란색 형광으로 칠한다. 표식은 `##`, `##.##`, `[확인 필요: …]` 세 가지다.**
이유: 미확정 값이 한눈에 보여야 확정 전에 빠짐없이 채울 수 있다.
- 금액이나 수량을 모르면 `##`, 연월을 모르면 `##.##`, 설명이 필요하면 `[확인 필요: 무엇이 필요한지]`로 쓴다.
- 대기 표식이 아닌 형광펜이나 빨간 글자(회사 담당자가 입력 표시로 칠한 것 등)는 사용자에게 물은 뒤 정리한다. 색만 정리하고 내용은 지우지 않는다.

**규칙 21. 반올림이나 단수 차이를 설명하는 문구, 작업 과정 문구를 표 주석에 쓰지 않는다. 합은 표 안에서 맞춘다.**
이유: 심사역이 궁금해하지 않는 내용이고 통과한 신청서에도 없다. 작업 과정은 대조표와 검토 기록에만 남긴다.
- 쓰지 않는 문구 예: 「천원 미만 반올림으로 합계와 차이가 날 수 있습니다」, 「결산자료를 기준으로 작성하였습니다」, 「원장에서 역산하였습니다」.
- 원 단위 자료를 천원으로 바꿀 때는 사사오입(ROUND_HALF_UP)을 쓴다. 파이썬 기본 `round()`는 짝수 쪽으로 반올림하므로 쓰지 않는다.
- 합계는 원 단위 합을 환산한 값으로 쓰고, 행의 합과 1천원이 어긋나면 가장 큰 행이나 「기타」 행에서 조정한다. 조정 내역은 대조표 엑셀에 적는다.

```python
from decimal import Decimal, ROUND_HALF_UP
def to_thousand(won):              # 원 → 천원, 사사오입
    return int((Decimal(won) / 1000).quantize(Decimal("1"), rounding=ROUND_HALF_UP))
```

**규칙 22. docx 산출물에는 출처 열과 원천 표기를 넣지 않는다.**
이유: docx는 거래소에 내는 산출물이다. 원천 추적은 대조표 엑셀과 마크다운 초안의 몫이다.
- 마크다운 초안에서는 표에 「출처」 열을 두어도 된다(검토용). docx로 바꿀 때 그 열을 뺀다.
- 「비고」 칸에 쪽수, 의사록 회차, 파일명, 시트명을 쓰지 않는다. 비고에는 산출물에 남을 내용만 쓴다.
- 변환 뒤 docx 전체에서 「출처」, 「p.」+숫자, 「.xlsx」, 「.pdf」, 「시트」, 「대조표」, 「이사회 N회」 같은 말을 찾아 0건인지 확인한다.
- 시장 보고서처럼 본문에 남겨야 하는 외부 출처만 `출처: 기관명, 자료명, 연도` 형식의 별도 줄로 쓴다.

### 바. 주기(주석)

**규칙 23. 비고 칸에 길게 쓰지 말고 주)로 뺀다.**
이유: 비고 열이 길어지면 다른 열의 폭을 빼앗고 행 높이가 커진다.
- 비고에는 「무상증자」, 「보통주 전환」 같은 짧은 말만 둔다.
- 칸에 한 줄로 안 들어가거나 문장이 되면 주)로 옮긴다.

**규칙 24. 주기는 표 바로 아래 빈 줄 없이 붙이고, 들여쓰기와 내어쓰기 없이 왼쪽에 붙여 쭉 이어 쓴다.**
이유: 표와 주기가 떨어지면 어느 표의 주기인지 헷갈린다. 내어쓰기를 하면 둘째 줄부터 들쭉날쭉해진다.
- 대상은 `주)`, `주1)`, `(*)`, `※`로 시작하는 문단이다.
- 글자는 9pt로 쓴다. 주기가 끝나면 본문과는 한 줄 띄운다.

**규칙 25. 주 번호를 행마다 반복하지 않고, 주기 하나에는 그 표의 사실만 쓴다.**
이유: 같은 「주3)」이 열 행에 붙으면 표가 지저분해진다. 다른 거래 이야기가 섞이면 독자가 그 표의 어느 행과 관련된지 찾지 못한다.
- 여러 행에 같은 설명이 필요하면 머리글이나 구분 칸에 표식을 한 번만 단다.
- 다른 증자, 다른 양수도, 다른 사건 이야기는 그 사건을 다루는 표 아래로 옮긴다.
- 주 번호는 표마다 주1)부터 다시 매긴다.

### 사. 표 종류별 규칙

**규칙 26. 임원 현황 표에서는 약력 열이 가장 중요하다.**
이유: 심사역이 임원 표에서 가장 오래 보는 칸이 약력이다.
- 주식 종류, 성별처럼 짧은 열은 좁게 해도 된다. 남는 폭은 모두 약력에 준다.
- 사용자가 정한 폭은 기준으로 쓰고, 숫자(보유 주식수)나 괄호 묶음(「(최대주주)」, 「(YY.MM.DD)」)이 안 들어갈 때만 넓힌다.
- 직위, 담당 업무, 관계, 비고는 규칙 14대로 나눈다. 예: 「대표이사 / (등기)」, 「경영총괄 / (CEO)」, 「본인 / (최대주주)」, 「사임 / (YY.MM.DD)」.

**규칙 27. 임원 약력은 정해진 서식으로 한 줄에 한 항목씩 쓴다.**
이유: 사람마다 형식이 다르면 비교가 안 되고 빠진 기간이 보이지 않는다.
- 학력: `YYYY.MM ○○대학교 ○○학과 학사`. 졸업 연월과 학위만 쓴다. 「졸업」이라는 말과 입학부터의 기간은 쓰지 않는다.
- 경력: `YYYY.MM~YYYY.MM ㈜○○ 직위`. 현직은 `YYYY.MM~현재`.
- 모르는 연월은 노란색 `##.##`로 둔다(예: `YYYY.##`). 사용자가 허락하면 앞뒤 경력에 맞춰 월을 넣는다.
- 영문 이력서는 같은 한글 서식으로 옮긴다.

**규칙 28. 주주 표(기초, 기말 열이 있는 표)는 같은 주주의 행을 기초에서 기말 순서로 쌓는다.**
이유: 위에서 아래로 읽으면 바뀐 과정이 그대로 보인다.
- 한 주주가 여러 종류의 주식을 가지면 기초 보유 행(예: 우선주)을 위, 기말 보유 행(예: 전환 후 보통주)을 아래에 둔다.
- 우선주가 보통주로 바뀐 변동 원인은 「보통주 전환」으로 쓴다.
- 성명 칸과 관계 칸은 같은 주주 안에서만 세로로 합친다. 다른 주주끼리 값이 같아도(예: 둘 다 「타인」) 합치지 않는다.
- 관계는 최대주주와의 관계로 쓴다. 관계가 없으면 「타인」이다. 「벤처금융」, 「FI」, 「개인」 같은 성격 표기는 관계 칸에 쓰지 않는다.
- 구분(최대주주등, 5% 이상 주주 등)마다 소계를 두고, 맨 아래에 합계(인원, 주식수, 지분율)를 둔다.
- 소액주주는 양식이 합산을 요구하는 변동표에서는 「N명」 한 행으로 합치고, 개별 나열을 요구하는 분포표에서는 한 명씩 쓴다. 양식을 보고 정한다.
- 증자나 양수도 내역은 그 표 아래 주N)으로 거래 단위로 쓴다.

**규칙 29. 자본금 변동 세부표는 합계 행과 주식 종류 표기를 맞춘다.**
이유: 주식 종류가 전환으로 바뀐 회사는 「당시 종류」와 「현재 종류」가 섞여 숫자가 안 맞아 보인다.
- 소계와 합계 행의 이름은 「합계」로 쓰고, 일자, 배정 대상, 주식 종류 칸을 가로로 합친다.
- 주식 종류는 취득(발행) 당시 종류로 쓴다.
- 현재 주식수 열 머리글에 `현재 주식수(보통주)`처럼 기준 종류를 밝힌다.

**규칙 30. 경영진 변동처럼 양식에 없는 표는 과거 신청서의 틀을 쓴다.**
이유: 규칙 1과 같다. 자주 쓰는 예를 적어 둔다.
- 경영진 변동: 시점별 직위 표. 열은 「변경일 | 대표이사 | 사내이사 | 기타비상무이사 | 사외이사 | 감사 | 변동 내용」이다.

### 아. 작업 방식

**규칙 31. 사용자나 회사가 고친 docx가 원본이 된 뒤에는 표를 초안에서 다시 만들지 않고 docx 칸을 직접 고친다.**
이유: 다시 만들면 사용자와 회사가 docx에서 고친 값, 지운 표식, 메모, 서식이 모두 사라진다.
- 고치기 전 원본을 보관 폴더에 복사해 두고, 결과는 다음 판 번호로 저장한다.
- 바꾼 칸마다 바꾸기 전과 후의 글자를 나란히 출력해 확인한다. 첫 줄이 다음 줄에 붙거나 지시문 일부가 남는 오류가 잦다.
- 서식 일괄 처리는 고칠 장에만 돌린다. 사용자가 손대지 말라고 한 장은 그대로 둔다.
- 끝나면 이전 판과 비교해 사라진 줄이 지시한 것뿐인지, 메모 수가 그대로인지 확인한다.

**규칙 32. 표는 그림으로 그려 눈으로 확인한다.**
이유: 열 폭 계산은 근사라서, 실제로 접히거나 잘리는 칸은 보아야 안다.
- Word나 LibreOffice에서 PDF로 내보내 보거나, 위의 글자 폭 함수로 칸마다 필요한 줄 수를 계산해 「짧은 정보가 접힌 칸」, 「숫자가 잘린 칸」, 「5줄 넘는 칸」 목록을 뽑는다.

## 3. 판단이 갈릴 때 기준

| 상황 | 기준 |
|---|---|
| 양식과 과거 신청서의 열 구성이 다르다 | 양식을 따른다. 양식에 없을 때만 과거 신청서를 쓴다 |
| 과거 신청서끼리 열 구성이 다르다 | 같은 업종, 최근 통과본, 2건 이상이 공통으로 쓰는 구성을 고른다. 고른 근거를 「표_대조」 시트에 적는다 |
| 사용자가 정한 서식과 이 문서가 다르다 | 사용자 것을 따르고 지침 파일에 날짜와 함께 적는다 |
| 사용자가 직접 바꾼 열 폭이 규칙과 다르다 | 사용자 값을 유지한다. 숫자가 잘릴 때만 넓히고 보고한다 |
| 짧은 글인지 긴 글인지 애매하다 | 그 열에 4줄 이상 접히거나 문장인 칸이 하나라도 있으면 긴 글(왼쪽)이다 |
| 「사임 (YY.MM.DD)」처럼 글과 날짜가 섞였다 | 날짜가 아니라 글이다. 「사임 / (YY.MM.DD)」로 줄을 나눈다 |
| 비고에 둘지 주)로 뺄지 애매하다 | 칸에 한 줄로 들어가는 명사구면 비고, 문장이거나 두 줄 이상이면 주) |
| 주기가 여러 표에 걸친 사건을 설명한다 | 각 표 아래에 그 표의 사실만 쓴다. 같은 문장을 두 표에 복사하지 않는다 |
| 같은 값인데 합칠지 애매하다 | 같은 주체(같은 주주, 같은 사업연도, 같은 거래)일 때만 합친다 |
| 9열 경계에 걸린다 | 병합 전 표 격자의 열 수로 센다. 8열 이하는 「20」을 생략하지 않는다 |
| 가운뎃점이 고유 표현인지 애매하다 | 법령, 고시, 양식에 그 표기가 그대로 나오면 유지한다. 아니면 쉼표나 「및」 |
| 글자를 줄여야 할지 애매하다 | 숫자가 잘릴 때만 줄인다. 긴 글의 줄 수가 늘어나는 것은 사유가 아니다 |
| `[확인 필요]` 때문에 칸이 길어진다 | 허용한다. 그 글자 때문에 다른 열 폭을 줄이지 않는다 |
| 회사가 칠한 색(형광펜, 빨간 글자)이 남아 있다 | 대기 표식이 아니면 사용자에게 묻고 정리한다. 내용은 지우지 않는다 |

## 4. 자주 하는 실수

- 가진 자료에 맞춰 열을 새로 만들거나 자료 없는 열을 지운다. → 양식 열을 그대로 두고 「-」이나 표식으로 채운다.
- 날짜 열이 숫자로 판정되어 오른쪽으로 붙는다. → 날짜를 숫자보다 먼저 판정한다.
- 접히는 글을 가운데 정렬한다. 또는 한 열 안에서 가운데와 왼쪽이 섞인다. → 열 단위로 한 번에 정한다.
- 폭이 모자라자 바로 글자를 8pt, 7pt로 줄인다. 「잘 보이게」 요청에도 글자를 줄인다. → 규칙 15 순서를 지킨다.
- 열을 균등하게 나눠 이름이 두 줄로 접히고 약력 칸은 남는다.
- Word 자동 줄바꿈에 맡겨 「상환전환우선 / 주」, 「1,234,5 / 67」처럼 잘린다.
- 같은 주 번호를 행마다 붙이거나, 한 주기에 다른 증자 이야기를 섞는다.
- 주기에 내어쓰기를 걸어 둘째 줄이 들여 쓰이거나, 표와 주기 사이에 빈 줄이 생긴다.
- 「천원 미만 반올림으로 차이가 날 수 있습니다」, 「결산자료로 작성」 같은 문구를 주석에 쓴다.
- 파이썬 `round()`로 반올림해 0.5 경계에서 1이 어긋난다.
- 비고 칸에 쪽수, 의사록 회차, 파일명이 남은 채 docx로 나간다.
- 머리행 색이 표마다 다르다(일부 표만 다른 색이 남음). 2단 머리행의 아래 행을 본문으로 보고 정렬한다.
- 표 안 0을 그대로 둔다. 음수를 「△」나 「-」로 쓴다.
- 9열 이상 표에서 일부 날짜만 「20」이 생략되어 형식이 섞인다.
- 다른 주주끼리 「타인」 칸을 세로로 합친다. 관계 칸에 「FI」, 「개인」이라고 쓴다.
- 우선주가 보통주로 바뀐 주주의 행 순서가 거꾸로다(기말 행이 위).
- 수정한 docx를 초안에서 다시 만들어 사용자가 지운 표식과 메모를 되살린다.
- 약력에 「졸업」, 「입학~졸업」 기간, 영문 원문을 그대로 남긴다.

## 5. 작업 끝 점검표

표의 틀
- [ ] 모든 표의 열 구성을 양식 또는 과거 신청서와 대조했고 「표_대조」 시트에 남겼다
- [ ] 자료가 없다고 열을 지운 표가 없다
- [ ] 해당 없는 표는 빈 표 대신 「해당사항이 없습니다」 문장으로 갈음했다
- [ ] 표 앞 안내 문장, `[표 제목]`, `(단위: …)`, 필요한 기준일이 있다
- [ ] 연도 열이 오래된 연도부터 최근 연도 순이다
- [ ] 합계와 소계 행이 굵고 이름이 「합계」, 「소계」로 통일되었다
- [ ] 같은 주체의 반복 값만 병합했다

서식
- [ ] 머리행(2단 포함)이 모두 `D9D9D9`, 굵게, 가운데, 세로 가운데다
- [ ] 표 칸과 본문의 줄간격이 1.0, 앞뒤 간격 0이다
- [ ] 한 표 안의 글자 크기가 모두 같다
- [ ] 열마다 정렬이 하나다(숫자 오른쪽, 날짜와 짧은 글 가운데, 긴 글 왼쪽)
- [ ] 접히는 글이 가운데 정렬된 칸이 없다
- [ ] 표 너비가 본문 폭과 같고 레이아웃이 고정이다

폭과 줄바꿈
- [ ] 숫자, 날짜, 괄호 묶음이 잘린 칸이 없다
- [ ] 이름 같은 짧은 정보가 접힌 칸이 없다
- [ ] 칸 안 줄바꿈이 의미 단위다
- [ ] 글자를 줄인 표가 있으면 표 이름과 크기를 사용자에게 보고했다
- [ ] 원래보다 글자가 작아진 표가 없다
- [ ] 표를 PDF나 그림으로 띄워 눈으로 확인했다

표기
- [ ] 0은 「-」, 음수는 괄호, 비율은 소수 둘째 자리다
- [ ] 9열 이상 표의 날짜가 모두 `YY.MM.DD`이고, 8열 이하 표는 `YYYY.MM.DD`다
- [ ] 예외가 아닌 가운뎃점(·)이 없다
- [ ] 대기 표식(`##`, `##.##`, `[확인 필요: …]`)이 모두 노란색이고, 그 밖의 형광펜과 빨간 글자는 사용자 확인을 거쳐 정리했다
- [ ] 반올림, 단수 차이, 작업 과정 문구가 없다
- [ ] 합계와 행의 합이 표 안에서 맞고, 조정 내역은 대조표에 적었다
- [ ] docx에 출처 열과 원천 표기가 0건이다

주기
- [ ] 비고 칸에 문장이 없다(문장은 주)로 옮김)
- [ ] 주기가 표 바로 아래 빈 줄 없이 붙어 있고 들여쓰기와 내어쓰기가 없다
- [ ] 같은 주 번호가 여러 행에 반복되지 않는다
- [ ] 각 주기에 그 표의 사실만 있다

표 종류별
- [ ] 임원 표의 약력 열이 가장 넓고, 학력과 경력이 정해진 서식이다
- [ ] 주주 표에서 같은 주주의 기초 행이 위, 기말 행이 아래이고, 성명과 관계 병합이 그 주주 안에서만 되어 있다
- [ ] 자본금 변동 세부표의 합계 행이 가로 병합되어 있고, 현재 주식수 머리글에 기준 종류가 있다

docx 작업본을 고친 경우
- [ ] 바꾼 칸마다 전후 글자를 확인했다
- [ ] 이전 판과 비교해 사라진 줄이 지시한 것뿐이고, 메모 수가 그대로다
