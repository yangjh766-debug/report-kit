# 02. 자료 가공과 숫자 검증 플레이북

> 코스닥 상장예비심사신청서의 숫자와 사실을 회사 원천자료에서 초안, Word 산출물까지 추적 가능하게 만들고, 스스로 다시 계산해 검증하는 방법이다. 특정 도구나 미리 만든 스크립트를 전제하지 않는다. 필요한 처리는 문서 끝 「부록: 코드 예시」의 짧은 파이썬(pymupdf, openpyxl, zipfile, python-docx, decimal)으로 시작하면 된다. 회사별로 달라지는 것(기준일, 회계기준 전환 연도, 연결 여부, 주주 거래 유형)은 각 프로젝트의 지침 파일과 설정 파일에 따로 적는다.

---

## 1. 언제 쓰나

- 신청서 초안에 **숫자를 처음 적기 전**. 장별 대조표 엑셀이 먼저 있어야 초안에 숫자를 쓸 수 있다.
- 회사에서 **새 자료(회신, 정정본, 추가 명세서)를 받았을 때**. 남은 `[확인 필요]`를 모두 다시 맞춰 본다.
- **기준일이 바뀔 때**(반기 → 3분기 → 연말). 대조표를 다시 계산하면 바뀐 행이 갱신 목록이 된다.
- 주관사, 회계법인 코멘트로 숫자를 고칠 때, 그리고 **Word(docx)로 변환하기 직전**.
- 주주변동표, 주주명부로 자본금 변동표, 주식 분포, 최대주주 변동표를 만들 때.

---

## 2. 폴더, 파일 구조

```
<프로젝트>/
├─ 원본자료/                 # git 제외. 읽기만 한다. 다른 폴더로 복사하지 않는다
│  ├─ 회사/                  # 회사가 준 원본(감사보고서, 정산표, 원장, 명세서, 의사록, 계약서, 명부)
│  ├─ 과거회사/              # 과거 용역 참고 자료(구조, 표현만 참고, 내용은 쓰지 않음)
│  └─ 외부의견/              # 주관사, 회계법인, 법무법인 코멘트
├─ 지침/                     # 작성, 서식, 검증 규칙, 장별 양식
├─ 초안/                     # 장별 마크다운. 숫자마다 (출처: …) 표기
├─ 검토/
│  ├─ 대조표_0N_장이름.xlsx  # 장 하나에 파일 하나. 예: 대조표_05_재무에관한사항.xlsx
│  ├─ 대조표_00_주주변동표.xlsx
│  ├─ 자료요청_전체.xlsx     # [확인 필요] 한 건 = 한 줄
│  ├─ 검토기록.md            # 사용자 승인, 반려, 원문과 회사 현황표가 다를 때의 판단
│  ├─ (스크립트 폴더)        # 추출, 대조표, 초안조립, 변환, 검사 코드(git 추적)
│  └─ _추출/                 # git 제외. 추출물 캐시(언제든 재생성 가능)
│     ├─ *.txt               # 감사, 검토보고서, 정관 등 쪽별 텍스트
│     ├─ *.json              # 주주명부, 계정별원장 월계, 총계정원장 월계
│     ├─ 스캔/<코드>/pNN.png # 스캔 PDF 쪽 그림, 스캔/색인.tsv(코드, 쪽수, 원본 경로)
│     ├─ 스캔요약/<코드>.md  # 스캔본 요약(근거 쪽 표기)
│     ├─ 엑셀그림/           # 엑셀 안에서 꺼낸 그림
│     ├─ 확인필요_목록.txt   # 초안 전체의 [확인 필요] 목록
│     └─ 재점검/             # 새 자료 수령 뒤 장별 재대조 결과
└─ 산출물/                   # 사용자가 "확정"한 장만
```

`.gitignore`에는 최소한 `원본자료/`와 `검토/_추출/`을 넣는다. 추출 캐시는 원본에서 파생된 기밀이므로 원본과 같은 수준으로 다룬다.

### 갖춰 둘 처리 단계

스크립트 이름은 자유롭게 정하되, 아래 단계가 각각 **다시 돌릴 수 있는 코드**로 있어야 한다. 손으로 한 번 하고 끝내면 기준일이 바뀌거나 자료가 정정될 때 같은 검증을 되풀이할 수 없다.

| 단계 | 하는 일 | 부록 |
|---|---|---|
| 추출 | 원본 → `_추출/` 캐시(보고서 쪽별 텍스트, 명부 JSON, 원장 월계 JSON). 새 세션의 첫 단계 | A |
| 스캔 렌더 | 글자 층 없는 PDF(쪽당 글자 수 기준 미만)를 쪽별 PNG로 렌더하고 색인 작성 | B |
| 엑셀 점검 | 숨김 시트, 그림, 숨은 행열, 셀 메모를 목록으로 내고 그림을 꺼냄 | C |
| 대조표 생성 | 장별 엑셀(원천 시트 복사 + 수식 + 파이썬 재계산 + 검증 열) | D, E |
| 초안 조립 | 엑셀, JSON에서 마크다운 표와 초안을 만듦 | — |
| docx 변환 | 마크다운 → 양식 스타일 docx, 출처 줄, 출처 열 제거 | — |
| docx 검사 | 원천 표기 잔존 건수, 표 열 너비, 정렬, 병합 점검 | F |
| 초안 검사 | 타사명, 금지 문구, 개인정보 패턴, 표 합계, 표식 건수 | G |
| 주주 거래 대조 | 주주변동표 거래 누계를 명부, 등기, 납입금액과 전수 대조 | 5.8절 |

## 3. 단계별 절차

숫자는 네 단계를 거치고, 각 단계가 파일로 남는다.

| 단계 | 무엇 | 어디에 |
|---|---|---|
| ① 원천 | 회사가 준 원본. 수정하지 않는다 | `원본자료/회사/` |
| ② 가공 | 원천 숫자를 어떻게 바꿨는지(단위 환산, 합산, 연환산, 재분류) | 대조표 「가공」 열, 처리 코드 |
| ③ 대조표 | 장별 엑셀. 초안 숫자 하나 = 한 행 | `검토/대조표_0N_장이름.xlsx` |
| ④ 초안 | 마크다운 초안의 숫자와 `(출처: …)` | `초안/0N_….md` |

③ 없이 ④에 숫자를 쓰지 않는다. 그 뒤 ⑤ docx는 ③, ④에서 코드로 만든다.

1. **추출 캐시를 만든다.** 작업을 새로 시작하면 대조표 계산보다 먼저 원본에서 텍스트, JSON을 뽑아 `검토/_추출/`에 둔다(부록 A). 임시 폴더(/tmp 등)는 작업 중에도 지워질 수 있으므로 다음 단계가 읽는 추출물은 반드시 프로젝트 안 git 제외 폴더에 두고, 언제든 재생성할 수 있게 한다.
2. **원천을 목록으로 만든다.** 이 장에서 쓸 파일마다 기준일, 감사, 검토 여부, 회계기준(K-GAAP/K-IFRS), 별도/연결, 스캔 여부를 「원천목록」 시트에 적는다.
3. **글자 없는 자료와 숨은 내용을 먼저 연다.** 스캔 PDF는 쪽별 그림으로 렌더해 읽고(부록 B), 엑셀은 숨김 시트, 그림을 점검한다(부록 C, 6절).
4. **대조표를 코드로 만든다.** 손으로 채우지 않는다. 코드가 원천에서 값을 읽고, 가공 규칙을 적용하고, 엑셀에는 수식으로, 별도 열에는 파이썬 계산값으로 같은 숫자를 두 번 만든다(4, 5절, 부록 D, E).
5. **「일치」 열을 본다.** X가 있으면 원인을 찾아 고치거나 「오류」 시트에 남긴다. 자료가 없어 못 채운 것은 「추가요청」 시트와 `검토/자료요청_전체.xlsx`에 한 줄씩 추가한다.
6. **초안을 조립한다.** 초안 숫자는 대조표, JSON에서 코드로 가져온다. 숫자 옆에 `(출처: 파일 p.쪽)` 또는 시트, 셀을 붙인다. 원천에 없는 숫자나 사실은 만들지 않고 `[확인 필요: …]`로 남긴다.
7. **서술도 검증한다.** 표 아래 문장(인원 수, 상대방, 사유, 채권자, 계약 조건, 규정 제정일)도 원장, 원문에서 세어 보고 대조표 「숫자」 시트에 한 행씩 올린다.
8. **교차 정합을 확인한다.** 같은 숫자가 다른 장에도 나오면 서로 같은지 본다(5.3절).
9. **docx로 변환하고 검사한다.** 변환할 때 `(출처: …)` 줄과 머리행이 출처, 근거, 원천인 열을 뺀다. 변환 뒤 docx 본문, 표에서 원천 표기를 찾아 건수를 낸다(부록 F). **0건이어야 한다.** 원천 추적은 대조표 엑셀의 몫이다.
10. **확정절차로 넘긴다.** 초안, 대조표 완성 → 문장 다듬기 → 사용자 검토 → "확정" → `산출물/`에 초안과 대조표를 함께 둔다. 대조표 없는 산출물은 없다. 커밋은 초안, 문장 다듬기, 확정 세 시점에만, 로컬에만 한다. 문장 다듬기 뒤 숫자를 고치면 5단계부터 다시 한다. 문장 다듬기 전후로 숫자가 하나도 바뀌지 않았는지 기계적으로 비교한다.
11. **새 자료가 오면 재점검한다.** `[확인 필요]` 목록을 다시 뽑아 장별로 전 자료와 재대조하고(6.3절), 대조표를 다시 계산해 달라진 행을 「오류」 시트에 기록한다.
12. **기준일이 바뀌면 롤포워드한다.** 지침의 기준일, 연도 열을 먼저 바꾸고, 새 원천을 「원천목록」에 추가한다(옛 파일은 지우지 않고 「대체됨」). 대조표를 다시 계산하면 「일치 X」 행이 갱신 대상이다. 고치는 순서는 재무(Ⅴ) → 회사 개황(Ⅰ) → 사업(Ⅳ) → 지배구조, 이해관계자 거래(Ⅶ) → 경영조직(Ⅱ) → Ⅲ, Ⅵ, Ⅷ이다. 재무를 먼저 고쳐야 다른 장이 그 숫자를 가져다 쓴다.

## 4. 대조표 엑셀 구조

파일 하나가 장 하나다. 아래 네 시트는 모든 대조표에 고정으로 두고, 원천과 표 시트는 장에 맞춰 더한다.

### 4.1 고정 시트

**「숫자」** — 한 행 = 초안 숫자(또는 검증할 사실) 하나

| 열 | 내용 |
|---|---|
| ID | `05-3-가-012` 형식(장-절-항-일련번호) |
| 초안 위치 | 표 제목 또는 문단 앞머리 |
| 항목 | 예: YYYY년 제품매출 |
| 기준 | 별도/연결(연결 대상 회사만), K-GAAP/K-IFRS |
| 초안 값 | 초안에 적힌 숫자 그대로 |
| 단위 | 천원 / 백만원 / 원 / 주 / % / 명 |
| 원천 파일 | `원본자료/회사/…` 상대 경로 |
| 원천 위치 | 쪽, 시트, 셀 |
| 원천 값 | 원본에 적힌 숫자 그대로(단위 변환 전) |
| 가공 | 바꾼 방법. 없으면 「그대로」 |
| 재계산 값 | 파이썬이 원천 값과 가공 규칙으로 다시 계산한 값 |
| 일치 | 재계산 값 = 초안 값이면 O, 아니면 X(수식으로) |
| 비고 | 판단 근거, 표 안 단수 조정 내역, 낮은 순위 원천을 쓴 이유 |

**「오류」** — 일치가 X인 행, 원천끼리 안 맞는 경우, 회사 현황표와 원문이 다른 경우. 열: ID, 내용, 원인 추정, 조치, 상태(미해결/해결), 발견일.

**「추가요청」** — 자료가 없어 `[확인 필요]`로 남긴 항목. 열: ID, 필요한 자료, 왜 필요한지(양식의 어느 표, 기재상의 주의), 요청일, 받은 날, 상태. 같은 내용을 `검토/자료요청_전체.xlsx`에도 한 줄 추가한다.

**「원천목록」** — 쓴 원천 파일, 기준일, 감사, 검토 여부, 회계기준, 스캔 여부, 대체 여부.

### 4.2 장에 따라 더하는 시트

| 시트 | 역할 |
|---|---|
| `원천_정산표YY_…` | 회사 정산표(엑셀) 시트를 **같은 셀 주소로 복사**. 요약표, 재무제표 셀은 이 시트를 수식으로 참조 |
| `원천_감사YY_GAAP`, `원천_감사YY_IFRS`, `원천_검토YY` | 감사, 검토보고서 PDF 파싱값(쪽 번호 포함). 연도, 회계기준별로 **따로 시트**(예: YYYY K-GAAP 감사, YYYY K-IFRS 전환, YYYY K-IFRS 비교표시) |
| `요약BS`, `요약PL`, `재무제표`, `제조원가` 등 표 시트 | 신청서 표와 같은 모양. 값은 원천 시트를 참조하는 수식, 옆에 「재계산」(파이썬 값)과 「검증」(수식 = 재계산) 열, 감사보고서와의 「차이」 수식 열 |
| `원장_월계`, `원장_거래처역산` | 월별, 거래처별 명세서의 집계 근거(5.6절) |
| `표_대조` | 양식, 과거 신청서에서 같은 표의 열 구성을 찾아 대조한 결과(열을 임의로 만들지 않기 위해) |
| `검증_…` | 교차 정합, 주주 거래 전수 대조 같은 묶음 검증 결과 |

### 4.3 엑셀 수식 연동 원칙

- 값만 박아 넣은 엑셀은 부족하다. 검토자(CFO, 주관사, 회계법인)가 셀을 클릭하면 원천 셀까지 따라갈 수 있어야 한다.
- 정산표 값과 감사보고서 값의 **차이를 수식으로** 계산한다. 0이 아니면 「오류」 시트에 올리고 어느 쪽을 채택했는지 근거를 적는다.
- 어느 회계기준을 썼는지 요약표의 「회계처리 기준」 행과 시트 이름으로 드러나게 한다.
- docx 표는 엑셀 표 시트에서 코드로 만든다. Word와 엑셀 사이에 실시간 연결은 두지 않는다. 엑셀이 바뀌면 Word를 다시 만든다.

## 5. 검증 방법

### 5.1 재계산 — 두 경로가 같아야 통과

1. **엑셀 수식 경로**: 원천 시트 → 수식 → 표 시트.
2. **파이썬 경로**: 코드가 원천에서 직접 읽어 같은 값을 계산해 「재계산」 열에 적는다.
3. 「검증」 수식이 두 값을 비교한다(부록 D). openpyxl은 수식을 계산하지 않으므로, 저장 뒤 Excel에서 한 번 열어 저장하고 `data_only=True`로 다시 읽어 불일치 건수를 세거나, 같은 식을 파이썬으로 평가해 대조한다.

### 5.2 내부 정합

- 표의 합계 = 항목 합, 소계 = 구간 합, 비율 = 분자/분모, 증감률 = (당기 − 전기)/전기.
- 자본: 기초 + 증가 − 감소 = 기말. 주식 분포: 기초 + 증가 − 감소 = 기말이고 기말 = 주주명부.
- 등기 자본금 = 발행주식총수 × 액면. 유상증자 행: 발행가 × 주식수 = 납입금액.

### 5.3 교차 정합(장 사이)

같은 숫자가 여러 장에 나오면 같아야 한다. 대표 목록:

| 숫자 | 나오는 곳 |
|---|---|
| 매출액 | 회사 개황 요약표, 재무제표 손익계산서, 사업의 내용 매출실적 합계 |
| 자산, 부채, 자본총계 | 회사 개황 요약표, 요약재무현황, 재무제표 |
| 발행주식수, 자본금 | 자본금 변동표, 주식 분포, 공모 사항, 재무상태표 자본금 |
| 임직원 수 | 경영조직, 사업의 내용(인력), 연구개발 조직 |
| 이해관계자 거래 | 지배구조 장, 재무제표 특수관계자 주석 |

별도와 연결이 둘 다 있는 회사는 두 세트를 따로 관리하고, 같은 값이어야 하는 항목(자본금, 발행주식수)도 양쪽에 각각 적어 교차 확인한다. 본문 재무 숫자는 별도 기준이 원칙이고, 연결은 양식이 연결을 요구하는 자리에만 쓴다.

### 5.4 원문 대조 — 숫자 말고 서술도

- 표 숫자만 검증하고 서술, 분류를 그대로 두는 것이 가장 흔한 누락이다. 인원 수, 거래 상대방, 증감 사유, 채권자명, 투자자 구분, 위원회 구성, 규정 제정 여부를 원문에서 세어 확인한다.
- **회사가 만든 현황 엑셀보다 원문(의사록, 계약서, 감사보고서 주석, 정관, 등기부)을 우선한다.** 둘이 다르면 원문으로 쓰고 「오류」 시트와 `검토기록.md`에 남긴다.
- 원문 요약을 다른 작업자에게 나눠 맡겼더라도, 신청서에 들어갈 사실은 원문(그림 포함)을 직접 다시 확인한다.

### 5.5 원천 우선순위

감사보고서 > 검토보고서 > 세무신고서 > 회사 내부 관리자료. 낮은 순위를 쓰면 「비고」에 이유를 적는다.

### 5.6 원장 집계 규칙

- **월별 귀속은 계정별원장의 `월계(YYYY-MM)` 행**으로 한다. 총계정원장의 손익 계정은 일자 없는 월계 행만 있어 활동 없는 달이 건너뛰어지고, 그 결과 월 귀속이 밀린다.
- 손익 계정에는 결산 대체분개가 있으므로 **수익은 대변, 비용은 차변만** 집계하고, 연간 합계를 감사보고서와 대조한다.
- 계정 구성 표에서 합계의 일정 비율(예: 5%, 과거 신청서 관행 10%) 미만 계정은 「기타」로 합친다. 기준은 장 지침에 적어 둔다.
- **거래처별 발생액**(매출, 매입)은 원장 관리항목(거래처) 열로 그대로 집계한다.
- **거래처별 기말잔액**은 원장에 거래처별 기초잔액이 없으면 거래처별 누적 최저치로 기초를 역산하고, 역산 기초 합계와 원장 기초의 차이를 「기타」에 넣어 합계를 보고서와 맞춘다. 잔여가 음수이면(거래처명 표기 불일치) 역산을 쓰지 않고 `[확인 필요]`로 두고 거래처별 잔액명세를 요청한다. 어느 쪽이든 `원장_거래처역산` 시트에 잔여와 사용 여부를 남긴다.

### 5.7 반올림과 단수차이

- 반올림은 파이썬 `decimal`의 `ROUND_HALF_UP`(사사오입)으로 한다(부록 E). 파이썬 기본 `round()`는 은행가 반올림(.5에서 짝수 쪽)이라 회계 관행과 어긋나고, float 계산은 오차가 생긴다.
- 합계는 **원 단위로 더한 뒤** 환산한다(환산한 값을 더하지 않는다).
- 행 합과 합계가 1단위 어긋나면 **표 안에서 맞춘다**: 가장 큰 행 또는 「기타」 행에서 조정하고, 조정 내역은 대조표 「비고」에만 남긴다.
- 「단위 미만 반올림으로 합계가 다를 수 있습니다」 같은 단수차이 설명, 「결산자료를 기준으로 작성」「원장에서 역산」「대조하였습니다」 같은 작업 과정 설명은 초안 본문, 주석 어디에도 쓰지 않는다. 심사역이 궁금해하지 않고, 통과한 신청서에도 없다.

### 5.8 주주변동표 워크북과 검증

주주변동표(세로형 증자, 양수도 내역)와 연도별 주주명부로 자본금 변동표, 주식 분포 변동, 신청일 주주분포, 최대주주 등 변동, 제3자배정, 벤처금융 현황, 최대주주 변동표를 만든다. 산출은 **수식 워크북**(`검토/대조표_00_주주변동표.xlsx`), 초안 조립이 읽는 **같은 값의 JSON**, **검증 결과** 세 가지다.

**워크북 시트**

| 시트 | 내용 |
|---|---|
| `원천_변동표` | 회사 주주변동표를 같은 셀 주소로 복사(가공 없음) |
| `원천_명부_시점1`~`시점3` | 주주명부 시점별 사본(예: 직전전 사업연도 말, 직전 사업연도 말, 최근 기준일). 개인정보 열은 빼고 옮긴다 |
| `설정` | 회사 특유 거래와 판별 규칙: 우선주 → 보통주 전환(일자, 비율, 대상), 신주발행 무효, 콜옵션, 상환 거래를 알아보는 비고 문구, 최대주주등 관계(본인, 배우자, 친인척, 등기/미등기 임원, 계열회사), 벤처금융, 기관투자자 판별 기준, 명의 표기 통일 규칙(㈜, (주), 띄어쓰기) |
| `거래내역` | 한 행 = 거래 한 건. 아래 열 구성 |
| `누계` | 주주, 주식종류별 시점 누계(거래내역에 SUMIFS 수식) |
| `표_자본금변동` | 양식 열 구성: 일자, 원인, 주식종류, 주식수, 주당 액면, 주당 발행가, 증자 후 자본금, 비고 등 |
| `표_1년변동`, `표_직전연도변동` | 주주별 기초, 증가, 감소, 기말 주식수와 지분율, 변동 사유(SUMIFS 수식 + 파이썬값 열) |
| `표_주주분포`, `표_최대주주등변동`, `표_제3자배정`, `표_벤처금융` | 신청서 표와 같은 모양 |
| `검증` | 아래 검증 항목별 수식 검산과 결과 |

**`거래내역` 열**: 일자, 거래유형(설립, 유상증자, 무상증자, 주식배당, 전환, 양수도, 상속증여, 무효, 상환, 콜옵션 행사 등 표준 유형), 주주명(표기 통일 후), 원문 주주명, 주식종류(보통, 우선 등), 증감 주식수(감소는 음수), 액면, 주당 발행가 또는 양수도 단가, 납입금액, 거래 상대방, 관계 구분, 원천 행 번호, 비고.

**검증 항목**

1. **명부 3개 시점 대조**: 각 시점의 거래 누계 = 명부(주주, 주식종류별 주식수 전부 일치).
2. **등기 자본금** = 발행주식총수 × 액면(등기부 기재값과 대조).
3. 유상증자 행마다 **발행가 × 주식수 = 납입금액**.
4. 표 내부: 기초 + 증가 − 감소 = 기말, 지분율 합계 100%, 표 사이 같은 시점 주식수 일치.
5. 최대주주 등 변동표와 양수도 주석의 거래일, 단가, 주식수가 거래내역에 있는지.

- 특수 거래(우선주 전환, 신주발행 무효, 콜옵션, 상환)는 계산 코드를 회사마다 고치지 않고 `설정` 시트(또는 설정 파일)에 규칙으로 적어 처리한다.
- 명부 대조 차이가 나면 먼저 ① 명의 표기 차이(㈜, (주), 띄어쓰기), ② 변동표 누락(우선주 전환, 무상증자 때 우선주 동시 발행, 상환)을 본다. 누락은 설정이나 원천 보정으로 해결하고 사용자에게 알린다. 숫자를 맞추려고 거래를 지어내지 않는다.
- 주식 양수도는 표 행마다 주석으로 상대방, 주식수, 단가를 풀어 쓴다. 단가가 자리표시인지 먼저 확인한다(6.4절).
- 1년 변동표 기준일은 신청 예정일이다. 확정 전에는 최신 주주명부 기준일을 쓰고 `[확인 필요]`를 남긴다.

### 5.9 docx 산출물 검사

- **원천 표기 잔존 0건**(부록 F): 출처, `원본자료/`, `.xlsx`, `.pdf`, `.docx`, `p.N`, 의사록 회차, 대조표, 자료 번호, 폴더, 시트명. `[확인 필요: …]` 안의 문구는 확정 전에 없어지므로 검사에서 뺀다.
- **표 검사**: 열 너비 균등 금지(내용 비례), 한 열 안의 정렬 혼재 금지, 2단 머리행 병합 여부. python-docx로 gridCol 너비, vMerge, gridSpan을 읽어 확인하고, 필요하면 표를 그림으로 그려 눈으로 본다.
- 신청서 본문에 꼭 남길 외부 출처(시장 보고서 등)는 `출처: 기관, 자료, 연도` 형식의 별도 줄로 쓴다. 이것은 원천 표기가 아니다.

## 6. 특수 상황

### 6.1 스캔 PDF

- 의사록, 계약서, 투자계약서, 주주간계약서는 대부분 **글자 층 없는 스캔본**이다. pymupdf 텍스트 추출이 빈 값으로 나오는데, 이것을 "내용 없음"으로 읽으면 안 된다.
- 새 PDF를 받으면 쪽당 글자 수가 기준(예: 50자) 미만인 파일을 골라 쪽별 PNG(`_추출/스캔/<코드>/pNN.png`)로 렌더하고 그림으로 읽는다(부록 B). PDF를 직접 이미지로 여는 도구가 환경에 따라 안 될 수 있으니 pymupdf 렌더를 기본으로 한다.
- 요약은 `_추출/스캔요약/<코드>.md`에 근거 쪽을 붙여 쓴다. 분량이 많으면 나눠 맡기되, 신청서에 들어갈 사실은 원문 그림을 직접 다시 본다.
- 회사가 만든 "의사록 현황" 같은 목록 엑셀에서 안건 제목만 가져오고 본문을 읽지 않으면, 위원회 구성, 참석 인원, 정기/임시 구분처럼 본문에만 있는 사실을 놓친다.

### 6.2 엑셀 안에 숨은 시트, 그림

- 명세서 엑셀에는 **숨김 시트(hidden, veryHidden)**와 **붙여 넣은 그림**(계약서, 증빙 스캔)이 들어 있을 수 있다. 예: 사용권자산 명세서 엑셀의 숨김 시트에 임대차계약서 스캔이 들어 있어, 임대 기간, 보증금, 임차료 같은 계약 조건을 원문으로 확인할 수 있었다.
- 새 엑셀을 받으면 시트 상태와 그림 유무를 먼저 목록으로 낸다(부록 C). 그림은 `_추출/엑셀그림/`(git 제외)에 꺼내 그림으로 읽는다. 숨은 행, 열, 셀 메모, 외부 연결 수식도 같이 본다.

### 6.3 새 자료가 오면 `[확인 필요]` 전수 재점검

- 새 자료가 올 때마다 `[확인 필요]` 목록을 다시 뽑아(부록 G) **장별로 전 자료와 재대조**한다. 결과는 `_추출/재점검/`에 두고 한 엑셀(장, 줄, 내용, 근거, 제안, 상태)로 묶어 사용자가 반영, 보류, 회사확인을 고르게 한다.
- 앞서 「확인 안 됨」이라 판단한 사실이 **다른 명세서에 있었던 사례**가 있다. 표식을 지우거나 회사에 요청하기 전에 추출 캐시 전체(텍스트, JSON, 스캔 요약)를 검색한다.
- 새 자료로 기존 서술이 틀린 것으로 드러나는 경우도 있다(예: "규정을 정할 예정"이라 썼는데 이미 제정됨, "채택하지 않음"이라 썼는데 정관에 조항이 있음). 표식만이 아니라 서술 전체를 원문으로 다시 본다.

### 6.4 자리표시 값(실제값이 아닌 값)

- 회사가 준 원장, 변동표의 값이 실제값이 아니라 **자리표시**일 수 있다. 예: 구주 양수도 단가가 전부 액면가로 적혀 있음, 날짜가 전부 월말로 적혀 있음, 같은 금액이 여러 행에 복사돼 있음.
- 판단 방법: 같은 표 안에서 **회사가 따로 회신한 값**(양수도 계약서, 세금 신고, 회사 답변)과 대조해 몇 행이 맞는지 본다. 균일한 값(모두 액면, 모두 0, 모두 같은 단가)이 반복되면 의심한다.
- 의심되면 그대로 쓰지 않는다. `[확인 필요: 양수도 단가 — 원천 표의 값이 액면가로 일괄 기재되어 실제 거래가 확인 필요]`로 남기고 회사에 확인하며, 「오류」 시트에 판단 근거를 적는다.

### 6.5 개인정보

- 주민등록번호, 개인 연락처, 자택 주소, 계좌번호 **열은 읽지도 출력하지도 않는다**. 코드는 머리행으로 그런 열을 찾아 건너뛰고(부록 C의 `개인정보_열` 예시), 행 전체를 화면에 찍지 않는다.
- 추출물, 대조표, 초안 어디에도 옮기지 않는다. 원본에 있다는 사실만 사용자에게 알린다.
- 생년월일처럼 신청서에 쓸 수도 있는 항목은 기재 동의 여부를 먼저 확인한다.
- 초안을 고칠 때마다 개인정보 패턴(주민번호, 휴대전화, 계좌번호)을 검사한다(부록 G).

### 6.6 원본 보호와 캐시

- `원본자료/`는 읽기만 한다. 수정, 이름 변경, 다른 폴더로 복사 금지.
- 추출 캐시(`검토/_추출/`)는 git 제외 폴더이고, 원본 파일 자체가 아니라 파생물(텍스트, JSON, PNG)만 둔다. 지워져도 추출, 렌더 코드로 다시 만들 수 있어야 한다.
- 임시 폴더는 임시 계산에만 쓰고, 다음 단계가 읽는 파일은 두지 않는다.

### 6.7 확정 뒤 원천이 바뀔 때

- 반기 검토 완료, 숫자 정정 등으로 원천이 바뀌면 대조표를 다시 계산해 달라진 행을 「오류」 시트에 기록하고 초안을 고친다. 확정본은 고치지 않고 `산출물/이전/YYYY-MM-DD/`로 옮긴 뒤 다시 확정받는다.

## 8. 점검표

### 장을 시작할 때
- [ ] 추출 캐시를 원본에서 다시 만들었다
- [ ] 새 PDF 중 스캔본을 쪽별 그림으로 렌더해 읽었다
- [ ] 새 엑셀의 숨김 시트, 그림, 숨은 행열, 셀 메모를 점검했다
- [ ] 「원천목록」에 기준일, 감사/검토 여부, 회계기준, 별도/연결을 적었다
- [ ] 이 장 표의 열 구성을 양식 → 과거 신청서 순으로 찾아 `표_대조`에 남겼다

### 대조표를 만들 때
- [ ] 대조표는 코드로 만들었다(손으로 채운 셀 없음)
- [ ] 정산표 시트를 같은 셀 주소로 복사하고 표 시트는 수식으로 참조한다
- [ ] 감사, 검토보고서 값은 연도, 회계기준별 시트에 쪽 번호와 함께 두고, 차이 수식이 있다
- [ ] 파이썬 「재계산」 열과 엑셀 수식 결과를 비교하는 「검증」 열이 있다
- [ ] 반올림은 `Decimal` `ROUND_HALF_UP`, 합계는 원 단위 합 뒤 환산
- [ ] 월별 금액은 계정별원장 `월계(YYYY-MM)` 기준, 수익 대변, 비용 차변만 집계
- [ ] 「일치」 열이 전부 O이거나, X는 모두 「오류」 시트에 원인, 조치와 함께 있다
- [ ] `[확인 필요]`마다 「추가요청」 시트와 `자료요청_전체.xlsx`에 한 줄씩 있다

### 초안과 서술
- [ ] 초안의 모든 숫자에 `(출처: …)`가 있고, 대조표 ID와 연결된다
- [ ] 표 아래 서술(인원 수, 상대방, 사유, 채권자, 계약 조건)도 원문으로 확인했다
- [ ] 회사 현황 엑셀과 원문이 다른 곳은 원문으로 쓰고 검토기록에 남겼다
- [ ] 자리표시로 보이는 값(일괄 액면가, 일괄 월말일 등)을 회사 회신값과 대조했다
- [ ] 교차 정합(매출액, 자산총계, 발행주식수, 자본금, 임직원 수, 이해관계자 거래)을 확인했다
- [ ] 단수차이 설명, 작업 과정 설명 문장이 없다(표 안에서 합을 맞춤)
- [ ] 개인정보 열을 읽거나 출력하지 않았고, 초안에 개인정보 패턴이 없다
- [ ] 타사명, 과거 신청서의 사실이 섞이지 않았다

### 주주변동표(해당 장)
- [ ] 워크북에 원천 사본, 설정, 거래내역, 누계(SUMIFS), 표, 검증 시트가 있다
- [ ] 명부 3개 시점 대조 전부 일치
- [ ] 등기 자본금 = 발행주식총수 × 액면
- [ ] 유상증자 행 발행가 × 주식수 = 납입금액 전부 일치
- [ ] 우선주 전환, 신주발행 무효, 콜옵션 등은 설정으로 처리했고 사용자에게 알렸다
- [ ] 변동표의 기초, 증감, 기말, 지분율, 합계, 최대주주 변동표와 양수도 주석을 거래내역과 전수 대조했다

### docx로 넘기기 전
- [ ] 원천 표기 잔존 검사 0건
- [ ] 출처, 근거, 원천 열이 docx에서 빠졌다
- [ ] 표 열 너비 비례, 열별 정렬 통일, 2단 머리행 병합 확인
- [ ] docx 표는 엑셀, JSON에서 코드로 다시 만든 것이다

### 새 자료를 받았을 때 / 기준일이 바뀔 때
- [ ] 추출 캐시를 다시 만들고 스캔 렌더를 돌렸다
- [ ] `[확인 필요]` 목록을 다시 뽑아 장별로 전 자료와 재대조했다
- [ ] 「확인 안 됨」을 지우거나 회사에 요청하기 전에 추출 캐시 전체를 검색했다
- [ ] 대조표를 다시 계산해 달라진 행을 「오류」 시트에 기록했다
- [ ] 기준일 변경 시 지침 → 원천목록 → 재계산 → Ⅴ부터 장 순서대로 수정 → 교차 정합 → 문장 갱신 순으로 했다
- [ ] 확정본은 고치지 않고 `산출물/이전/YYYY-MM-DD/`로 옮긴 뒤 다시 확정받았다

### B. 스캔 PDF를 쪽별 PNG로 렌더

```python
import fitz, pathlib

def 스캔여부(pdf, 기준=50):
    doc = fitz.open(pdf)
    return all(len(p.get_text("text").strip()) < 기준 for p in doc)

def 렌더(pdf, 코드, dpi=150):
    out = pathlib.Path("검토/_추출/스캔") / 코드
    out.mkdir(parents=True, exist_ok=True)
    doc = fitz.open(pdf)
    for i, page in enumerate(doc, 1):
        page.get_pixmap(dpi=dpi).save(out / f"p{i:02d}.png")
    with open("검토/_추출/스캔/색인.tsv", "a", encoding="utf-8") as f:
        f.write(f"{코드}\t{len(doc)}\t{pdf}\n")

for i, pdf in enumerate(sorted(pathlib.Path("원본자료/회사").rglob("*.pdf")), 1):
    if 스캔여부(pdf):
        렌더(pdf, f"X{i:02d}")
```

### C. 엑셀 숨김 시트, 그림 점검, 개인정보 열 건너뛰기

```python
import openpyxl, zipfile, pathlib, re

def 엑셀_점검(경로):
    wb = openpyxl.load_workbook(경로)          # 수식도 보려면 data_only=False(기본)
    for ws in wb.worksheets:
        숨은행 = [r for r, d in ws.row_dimensions.items() if d.hidden]
        숨은열 = [c for c, d in ws.column_dimensions.items() if d.hidden]
        print(ws.title, ws.sheet_state,           # visible / hidden / veryHidden
              "그림", len(getattr(ws, "_images", [])), "숨은행", len(숨은행), "숨은열", len(숨은열))
    out = pathlib.Path("검토/_추출/엑셀그림") / pathlib.Path(경로).stem
    with zipfile.ZipFile(경로) as z:               # openpyxl이 못 읽는 그림까지 꺼낸다
        for n in z.namelist():
            if n.startswith("xl/media/"):
                out.mkdir(parents=True, exist_ok=True)
                (out / pathlib.Path(n).name).write_bytes(z.read(n))

개인정보 = re.compile(r"주민|등록번호|연락처|전화|휴대|주소|계좌")

def 개인정보_열(ws, 머리행=1):
    return {c.column for c in ws[머리행] if c.value and 개인정보.search(str(c.value))}

def 안전하게_읽기(ws, 머리행=1):
    빼기 = 개인정보_열(ws, 머리행)
    for row in ws.iter_rows(min_row=머리행 + 1):
        yield {ws.cell(머리행, c.column).value: c.value for c in row if c.column not in 빼기}
```

### D. 대조표: 원천 시트 복사 + 수식 + 파이썬 재계산 + 검증

```python
import openpyxl
from openpyxl.utils import get_column_letter

src = openpyxl.load_workbook("원본자료/회사/정산표_YYYY.xlsx", data_only=True)["정산표"]
wb = openpyxl.Workbook(); wb.remove(wb.active)

# 1) 원천 시트를 같은 셀 주소로 복사(값만, 가공 없음)
원천 = wb.create_sheet("원천_정산표YY")
for row in src.iter_rows():
    for c in row:
        if c.value is not None:
            원천.cell(c.row, c.column, c.value)

# 2) 표 시트: 값은 원천 셀을 참조하는 수식, 옆에 파이썬 재계산과 검증 수식
표 = wb.create_sheet("요약PL")
표.append(["항목", "값(수식)", "재계산(파이썬)", "검증", "감사보고서", "차이"])
항목 = [("매출액", "D10"), ("매출원가", "D11")]          # 원천 셀 주소는 예시
for i, (이름, 셀) in enumerate(항목, start=2):
    재계산 = src[셀].value                                 # 같은 값을 파이썬 경로로 다시 읽음
```

### E. 반올림(ROUND_HALF_UP)과 표 안 단수 조정

```python
from decimal import Decimal, ROUND_HALF_UP

def 천원(원):
    return int((Decimal(str(원)) / 1000).quantize(Decimal("1"), rounding=ROUND_HALF_UP))

def 비율(분자, 분모, 자리=2):
    return (Decimal(str(분자)) / Decimal(str(분모)) * 100).quantize(
        Decimal(1).scaleb(-자리), rounding=ROUND_HALF_UP)

def 천원표(행들):                       # 행들: {"항목": 원 단위 금액}
    합계 = 천원(sum(행들.values()))    # 원 단위로 더한 뒤 환산
    표 = {k: 천원(v) for k, v in 행들.items()}
    차 = 합계 - sum(표.values())
    if 차:                              # 가장 큰 행(또는 「기타」)에서 조정, 내역은 대조표 비고에
        큰행 = max(표, key=lambda k: abs(표[k]))
        표[큰행] += 차
    return 표, 합계, 차
```

### F. docx 원천 표기 잔존 검사

```python
import docx, re

원천표기 = re.compile(r"출처|원본자료/|\.xlsx|\.pdf|\.docx|\bp\.\s?\d+|대조표|시트|_추출|"
                      r"(이사회|주주총회|주총)\s?(제)?\d+\s?회")

def 잔존검사(경로):
    d = docx.Document(경로)
    글 = [p.text for p in d.paragraphs]
    for t in d.tables:
        for row in t.rows:
            글 += [c.text for c in row.cells]
    건 = []
    for s in 글:
        s2 = re.sub(r"\[확인 필요[^\]]*\]", "", s)    # 확정 전 표식 안 문구는 제외
        if 원천표기.search(s2):
            건.append(s2.strip()[:80])
    print("원천 표기 잔존", len(건), "건")           # 0건이어야 한다
    for x in 건: print(" -", x)
    return len(건)
```

본문에 꼭 남겨야 하는 외부 출처 줄(`출처: 기관, 자료, 연도`)이 있으면, 그 줄 형식을 예외 패턴으로 따로 두고 검사에서 뺀다.

### G. 초안 검사: `[확인 필요]` 목록, 개인정보 패턴, 금지 문구, 타사명

```python
import re, pathlib
```
