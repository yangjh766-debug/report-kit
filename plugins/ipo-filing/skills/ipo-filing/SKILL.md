# 상장예비심사신청서 작성

거래소 제출 서식을 쓰는 작업이다. 내부 검토보고서 양식(회색톤, 개조식, 「내부 검토자료」 머리글)과 섞지 않는다.

## 어떤 지침을 따르나

1. **프로젝트 폴더에 `지침/`과 CLAUDE.md가 있으면 그것이 기준이다.** 이 스킬의 references는 참고만 한다. 프로젝트 지침과 다르면 프로젝트 지침을 따른다.
2. 새 회사 착수처럼 프로젝트 지침이 아직 없으면 references의 범용 플레이북으로 시작하고, 첫날 프로젝트 `지침/`을 만든다(01 문서 2절).

## 새 신청서 프로젝트를 시작할 때 (착수 첫날 자동으로 할 것)

사용자가 "새 회사 신청서 착수하자"처럼 말하면, references의 01 문서 2절을 따르기 전에 아래를 먼저 한다.

1. 회사별 작업 폴더를 따로 만든다(예: `~/Documents/ipo-회사명`). 다른 업무 폴더 안에서 신청서를 쓰지 않는다. 기밀 자료가 섞이지 않게 하고, 보고서 양식과도 나누기 위해서다.
2. 그 폴더의 `.claude/settings.json`에 보고서 플러그인을 끄는 설정을 넣는다(이미 있는 설정은 지우지 않고 합친다).
   ```json
   { "enabledPlugins": { "report-kit@report-kit": false } }
   ```
3. 그 폴더의 CLAUDE.md 맨 위에 다음 절을 넣는다.
   ```markdown
   ## 다른 보고서 양식과 섞지 않기
   - 이 프로젝트의 산출물은 상장예비심사신청서다. 양식과 문체는 `지침/`과 거래소 양식만 따른다. 본문은 서술식 경어체이고 개조식을 쓰지 않는다.
   - 회색톤 검토보고서 양식(제목 이중선, 개조식, 「내부 검토자료」 머리글)을 만드는 스킬은 이 프로젝트에서 쓰지 않는다.
   ```
4. `지침/`에 references의 `워딩규칙_예시.md`, `용어집_예시.md`를 복사해 회사에 맞게 고친다.
5. 사용자에게 "새 대화부터 보고서 플러그인이 이 폴더에서 꺼진다"고 알린다.

이미 다른 폴더(보고서 플러그인이 켜진 곳)에서 신청서 요청이 오면, 그 자리에서 쓰지 말고 위 1~3을 먼저 제안한다.

## 핵심 원칙

- 원본에 없는 숫자와 사실은 만들지 않는다. 모르면 노란 `##` 또는 `[확인 필요: …]`로 두고 자료요청 리스트에 한 줄을 추가한다.
- 숫자는 대조표 엑셀에서 재계산으로 검증한 뒤에 초안에 쓴다. 출처는 엑셀과 초안 md에만 두고, 제출용 docx에는 남기지 않는다.
- 본문은 서술식 경어체(「~습니다」). 개조식, 회색톤 검토보고서 양식은 쓰지 않는다.
- 표는 거래소 양식, 그다음 과거 신청서의 열 구성을 따른다. 머리행은 양식 원본 색, 글자 크기는 줄이지 않는 쪽으로 맞춘다.
- 문장 다듬기는 report-kit 플러그인의 wording 스킬에 프로젝트 `지침/워딩규칙.md`와 `지침/용어집.md`를 `--style`로 넘겨서 한다. report-kit의 문체 파일은 넘기지 않는다. 처음이면 references의 `워딩규칙_예시.md`, `용어집_예시.md`를 고쳐 프로젝트 지침으로 만든다.
- 신청서 작업 폴더에서는 report-kit 플러그인을 꺼 두면 보고서 양식이 섞일 일이 없다: `.claude/settings.json`에 `"enabledPlugins": {"report-kit@report-kit": false}`. wording 스킬이 필요하면 개인 스킬로 따로 둔다.
- 사용자나 회사가 고친 docx가 생기면 그 파일이 원본이다. 다른 팀이 맡은 장은 건드리지 않는다.
- 회사 자료는 기밀이다. 외부 저장소에 올리지 않고, 개인정보는 옮기지 않는다.
