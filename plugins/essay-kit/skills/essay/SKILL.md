# 에세이 위임 (코덱스가 처음부터 집필)

## 왜 따로 두나 (2026-10-16 사용자 판단)

링크드인 글을 「클로드 초안 → /wording 다듬기」로 만들었더니 딱딱 끊기고 리듬이 없었다. 다듬기는 구조를 못 바꾸고, 「짧게」 규칙이 이어진 문장을 쪼갰고, 코덱스가 생각 없이 돌았다. 그래서 에세이는 역할을 뒤집는다. 사실은 클로드가 책임지고, **주제와 구성과 문장은 코덱스가** 짓는다.

| | wording | essay |
|---|---|---|
| 클로드가 쓰는 것 | 완성 초안 | 재료(사실 목록), 고칠 점 메모 |
| 코덱스가 하는 일 | 문장만 다듬기(1,000자 조각) | 주제 뽑기, 구성부터 전문 집필 |
| 생각 수준 | 기본 | high |
| 검사 | 숫자·표식 하나라도 다르면 버림 | 필수 문구·새 숫자는 빨강, 어미 반복은 노랑, 리듬은 참고 |
| 고칠 때 | 다시 다듬기 | 클로드가 직접 고치지 않고 고칠 점을 코덱스에 돌려보냄 |

## 2026-10-19에 배운 것 (처음 글이 나빴던 이유)

지인과의 메신저 대화로 AX 에세이를 쓰다가 처음 판이 「주제의식이 별로, 흐름도 별로」였다. 원인은 모두 클로드의 재료 정리였다.

- 대화를 순서대로 전부 재료에 넣었다 → 글이 대화 요약이 되고 생각 하나가 서지 않았다. **원재료가 길면 주제부터 뽑는다(0단계).**
- 재료를 다 담게 했다 → 대화 순서대로 흘렀다. **주제 하나에 필요한 재료 두세 개만 남긴다.**
- 구호(「사이보그가 되지 말자」)를 「그대로 넣을 것」에만 넣었다 → 뜬금없이 튀어나왔다. **구호에는 그 말이 나온 맥락도 재료에 적는다.**
- 「재료에 없는 건 쓰지 말라」가 생각까지 막았다 → 얇았다. **의견 글은 「살을 붙여도 되는 것」을 기본으로 둔다.**
- 가장 크게 좋아진 계기는 **사용자가 마음에 든 문단을 골라 주고, 그 문단을 정점에 두고 다시 쓴 것**이었다.
- 그다음 **이음새를 구체적으로 짚어 돌려보내자**(시간이 거꾸로 감, 화제가 다리 없이 들어옴 등 다섯 군데) 흐름이 살았다.

## 절차

### 0. 먼저 묻기 (클로드)
재료를 만들기 전에 사용자에게 네 가지를 묻는다. 이미 알면 건너뛰고, 모르는 것만 한 번에 묻는다(AskUserQuestion으로 선택지를 주면 빠르다).
1. **어디에 올리나(매체)와 말투.** 링크드인만 쓰는 스킬이 아니다. 스레드나 카톡처럼 더 가벼운 매체일 수 있다. 매체가 정해지면 아래 「매체별 기본값」을 따른다. 말투(반말 평서체, 「~요」체, 「~습니다」체)도 같이 묻는다.
2. 등장인물을 어떻게 부를지, 관계가 무엇인지(예: 「선배」가 아니라 「전 직장 동료이자 다른 회사 CFO인 형」).
3. 어디까지 공개해도 되는지(이름, 회사, 업종, 상대의 계획). 기본은 모두 빼고 관계만 남긴다.
4. 원하는 결론과 톤(진지하게, 재밌게, 철학적으로).

#### 매체별 기본값
| 매체 | 분량 | 문체 규칙(`--style`) | 서식 | 제목 | 해시태그 |
|---|---|---|---|---|---|
| 링크드인 | 900~2,000자 | `linkedin.md` | 마크다운 없음, 목록은 `•`, 문단 사이 빈 줄 | 첫 줄에 한 줄 제목 | 3~5개, 맨 끝 |
| 스레드, X | 150~500자(X는 280자 안팎, 길면 이어 쓰기) | `가벼운글.md` | 한두 줄마다 줄바꿈, 목록 없음 | 없음, 첫 줄이 제목 | 0~2개 |
| 인스타그램 캡션 | 200~800자 | `가벼운글.md` | 줄바꿈 많이, 첫 줄 후킹 | 없음 | 끝에 몇 개(사용자에게 확인) |
| 카톡, 메신저 공유 | 100~400자 | `가벼운글.md` | 마크다운 없음, 짧은 문단 | 없음 | 없음 |
| 블로그, 브런치 | 2,000~5,000자 | `linkedin.md` | 소제목(##) 가능, 마크다운 그대로 | 있음 | 없음(블로그는 태그 칸에 따로) |
| 뉴스레터 | 1,500~4,000자 | `linkedin.md` | 인사 한 줄, 소제목 가능, 끝에 다음 호 예고 | 있음 | 없음 |
| 사내 게시판 | 600~1,500자 | `linkedin.md` + 말투는 「~습니다」 | 마크다운 없음 | 있음 | 없음 |

어느 매체든 재밌게를 원하면 `재밌게.md`를 덧붙인다. 매체 기본값과 사용자가 말한 것이 다르면 사용자 말을 따른다. 재료의 「어디에 올리고 누가 읽나」에 매체, 말투, 분량을 적는다.

### 1. 주제 뽑기 (코덱스) — 원재료가 대화·메모·회의록처럼 길면 반드시
원재료를 익명 처리해(이름·회사 삭제, 쪼개진 메시지는 문장으로 잇되 말은 원문 그대로) `brief.md`로 두고 주제 후보를 뽑는다. 후보마다 제목, 핵심 주장, 왜 뻔하지 않은가, 첫 문장, 쓸 재료, 약점, 끝에 추천이 나온다.

```bash
export PATH="$HOME/.local/node/bin:$PATH"
cd <작업 폴더>/주제
python3 "${CLAUDE_PLUGIN_ROOT}/skills/essay/write.py" brief.md topics.md --topics 6
```

후보를 표로 보여 주고 클로드 의견을 한두 줄 붙여 사용자가 고르게 한다. 둘 이상 고르면 따로 쓰거나, 하나를 큰 줄기로 두고 나머지를 받침으로 묶는다.

### 2. 주제 하나로 재료 만들기 (클로드)
`${CLAUDE_PLUGIN_ROOT}/skills/essay/brief_template.md`를 복사해 채운다. 고른 주제에 필요한 재료만 남기고 나머지는 버린다. `[필수]`는 두세 개만. 제목은 「제목」 절에. 의견 글이면 「살을 붙여도 되는 것」에 생각의 방향을 몇 개 적는다(「그대로 쓰지 말고 네 말로」). 사용자가 직접 한 말은 「글쓴이 말투」에 원문 그대로.

### 3. 두 판 쓰기 (코덱스)
한 판에 1분쯤. 「재밌게」를 원하면 문체 규칙을 덧붙인다.

```bash
S="${CLAUDE_PLUGIN_ROOT}/skills/essay"
python3 $S/write.py brief.md post.md --n 2                                  # 기본 문체
python3 $S/write.py brief.md post.md --n 2 --style $S/styles/linkedin.md --style $S/styles/재밌게.md
```

보고서를 보고 두 판을 보여 준 뒤, **사용자에게 「가장 마음에 드는 문단」을 묻는다.**

### 4. 핵심 문단을 정점에 두고 다시 쓰기 (코덱스)
고른 문단을 재료의 「핵심 문단」에 원문 그대로 붙이고, 그 안의 핵심 문장 두세 개는 「그대로 넣을 것」에도 넣는다. 「이 글로 하고 싶은 말」에 「글 전체가 이 문단으로 모인다, 3분의 2 지점, 앞 장면은 계단」이라고 적는다. 앞 판에서 사용자가 좋아한 문장은 「앞 판에서 살릴 문장」에. 다시 두 판을 쓴다.

### 5. 이음새 진단 → 돌려보내기 1~2회 (클로드 진단, 코덱스 수정)
클로드가 문장을 직접 고치지 않는다(손대면 다시 딱딱해진다. 한 문단 안 같은 어미가 겹친 정도의 한 단어 수정만 예외로 하고 사용자에게 알린다). 아래 점검표로 어색한 곳을 **구체적으로** 짚어 `notes.md`에 적는다.

이음새 점검표:
- 시간이 거꾸로 가거나 같은 말을 두 번 꺼내는 곳(첫 문단에서 한 말을 셋째 문단에서 「그러면서도 ~를 꺼냈다」로 또 꺼냄)
- 화제가 다리 없이 들어오는 곳(블랙박스 → 갑자기 지출결의서)
- 앞뒤 문단 사이에 이유가 빠진 곳(회의 이야기 → 이유 없이 내부회계)
- 깔아 주지 않은 한 줄 결론이나 구호
- 같은 어미 반복(「~고 했다」 「~면 좋겠다」), 덧붙인 느낌의 마지막 문장

```bash
python3 $S/write.py brief.md post_flow.md --revise post_2.md --notes notes.md --compare post_2.md
```

### 6. 사실 대조, 제목, 전달 (클로드)
결과를 재료와 한 줄씩 대조한다.
- 재료에 없는 사건, 사람, 숫자, 대사가 들어갔는가
- **제안이나 다짐이 습관이나 사실로 바뀌었는가**(「5영업일을 두자고 했다」 → 「나는 5영업일을 둔다」는 틀림)
- **인용이 한 글자라도 바뀌었는가**(「안 중요해요」 → 「별로 안 중요해요」는 틀림)
- 호칭과 관계가 0단계에서 정한 대로인가

매체별 서식(위 표)에 맞춰 붙여 넣을 파일(`<매체>.txt`, 블로그는 `.md`)로 저장하고 `pbcopy`로 클립보드에 넣는다. 링크드인, 스레드, 카톡은 마크다운이 그대로 보이므로 `**`, `##`, `- `를 남기지 않는다(목록은 `•`). 제목이 없으면 후보 서너 개를 제안한다. 실존 인물 이야기가 담기면 올리기 전에 당사자에게 물어보라고 한 줄 덧붙인다.

## 주의

- 게시나 외부 공유 전에는 반드시 전문을 사용자에게 먼저 보여 준다.
- 코덱스 호출마다 사용자의 ChatGPT 사용량이 든다. 생각 수준 high로 짧은 글 한 판에 약 1~2만 토큰, 1분 안팎.
- codex exec는 stdin이 열려 있으면 멈춘다. 스크립트는 stdin을 닫고, 시간 초과 시 자손 프로세스까지 죽인다.
- 로그인이 풀렸으면 `codex login status`로 확인하고 사용자에게 `codex login`을 안내한다.
- 리듬 지표(변동계수)는 참고용이다. 내용이 풍부해지면 문장이 길어져 수치가 내려가기도 한다. 등급은 필수 문구, 새 숫자, 금지 표현, 어미 반복으로만 정한다.
- 회사 기밀 자료로 에세이를 쓰지 않는다. 원재료를 코덱스에 넘기기 전에 이름과 회사를 지운다.
- 실존 인물과의 대화로 쓴 글은 전후 비교를 내 컴퓨터에만 두고 공개 저장소에 올리지 않는다.
