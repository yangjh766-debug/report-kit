# 에세이 위임 (코덱스가 처음부터 집필)

## 왜 따로 두나 (2026-10-16 사용자 판단)

링크드인 글을 「클로드 초안 → /wording 다듬기」로 만들었더니 딱딱 끊기고 리듬이 없었다. 원인은 셋이었다.

1. **다듬기는 구조를 못 바꾼다.** wording은 숫자와 구조를 지키며 문장만 고치게 만든 도구다. 클로드 초안이 「하고 싶은 말을 하나씩 늘어놓는」 구성이면, 장면에서 요령으로 갑자기 넘어가는 이음새 문제는 다듬기로 고쳐지지 않는다.
2. **규칙이 끊으라고 시켰다.** 「문단은 짧게, 문장은 담백하게」를 받은 코덱스가 이어진 문장(「~고」「~자」)을 마침표로 쪼갰다. 모든 문장이 비슷한 길이에 「~다.」로 끝났다.
3. **생각 없이 돌았다.** 코덱스 생각 수준이 none이라 흐름은 따지지 않고 문장만 고쳤다.

그래서 에세이는 역할을 뒤집는다. 사실은 클로드가 책임지고, **구성과 문장은 코덱스가 처음부터** 짓는다. wording 규칙에 섞지 않은 것은, 신청서·보고서에 필요한 「구조와 숫자를 지킨다」는 규칙과 에세이에 필요한 「구조부터 새로 짠다」는 규칙이 서로 부딪히기 때문이다.

| | wording | essay |
|---|---|---|
| 클로드가 쓰는 것 | 완성 초안 | 재료(사실 목록)만 |
| 코덱스가 하는 일 | 문장만 다듬기(1,000자 조각) | 구성부터 전문 집필(통째로) |
| 생각 수준 | 기본 | high |
| 검사 | 숫자·표식 하나라도 다르면 버림 | 필수 문구 누락·새 숫자는 빨강, 리듬 지표 보고 |
| 고칠 때 | 다시 다듬기 | 클로드가 직접 고치지 않고 고칠 점을 코덱스에 돌려보냄 |

## 절차

1. **재료 정리(클로드).** `${CLAUDE_PLUGIN_ROOT}/skills/essay/brief_template.md`를 복사해 채운다. 문장으로 다듬지 말고 사실을 목록으로 적는다.
   - 꼭 들어갈 사실은 `[필수]`, 글자 하나 바뀌면 안 되는 것(링크, 해시태그 줄, 목록 항목, 꼭 쓸 문장, 끝 질문)은 「그대로 넣을 것」에 한 줄씩.
   - 글에 나올 수 있는 숫자는 모두 「숫자」에 적는다. 여기 없는 숫자가 나오면 빨강이다.
   - **사용자가 직접 쓰거나 고친 문장은 「글쓴이 말투」에 원문 그대로** 모은다. 코덱스가 글쓴이 목소리를 내는 근거다.
   - 재료가 모자라면 지어내지 말고 사용자에게 질문 목록으로 먼저 묻는다.
2. **집필(코덱스).** 재료 파일이 있는 폴더에서 실행한다. 두 판은 서로 다른 시작(장면/고백)을 시도한다. 1판에 2~4분, run_in_background로 돌린다.

```bash
export PATH="$HOME/.local/node/bin:$PATH"
cd <작업 폴더>
python3 "${CLAUDE_PLUGIN_ROOT}/skills/essay/write.py" brief.md post.md --n 2
# 기존 글과 리듬을 비교하려면 --compare 기존글.md
# 다른 문체가 필요하면 --style 규칙.md (여러 번 가능, 없으면 styles/linkedin.md)
```

3. **검사(스크립트 + 클로드).** `post.report.md`를 먼저 본다.
   - 빨강(필수 문구 누락, 재료에 없는 숫자): 그 판은 쓰지 않는다. 다시 돌리거나 고칠 점으로 돌려보낸다.
   - 노랑(금지 표현, 리듬 경고): 보여 주되 해당 부분을 짚는다.
   - 그다음 클로드가 결과 문장을 재료와 한 줄씩 대조해, **재료에 없는 사실·감정·대사가 들어갔는지** 본다. 기계 검사는 숫자와 필수 문구만 잡는다.
4. **고치기.** 클로드가 문장을 직접 고치지 않는다(손대면 다시 딱딱해진다). 고칠 점을 `notes.md`에 적어 돌려보낸다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/essay/write.py" brief.md post_fix.md --revise post_1.md --notes notes.md
```

5. **보여 주기.** 두 판을 나란히 보여 주고 리듬 지표 표와 각 판의 시작 방식을 한두 줄로 짚는다. 사용자가 고른 판에 직접 손대면, 고친 문장을 다음 재료의 「글쓴이 말투」에 쌓는다.

## 주의

- 코덱스 호출마다 사용자의 ChatGPT 사용량이 든다. 생각 수준 high로 짧은 글 한 판에 약 1~2만 토큰.
- codex exec는 stdin이 열려 있으면 멈춘다. 스크립트는 stdin을 닫고, 시간 초과 시 자손 프로세스까지 죽인다(wording과 같은 처리).
- 로그인이 풀렸으면 `codex login status`로 확인하고 사용자에게 `codex login`을 안내한다.
- 리듬 지표의 「길이 변동계수」는 문장 길이가 얼마나 섞였는지다. 0.4 미만이면 끊기는 느낌이 나기 쉽다. 지표는 참고용이고 최종 판단은 읽어 보고 한다.
- 회사 기밀 자료로 에세이를 쓰지 않는다. 재료에 회사 실명·숫자가 들어가면 사용자에게 먼저 확인한다.
