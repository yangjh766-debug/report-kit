# essay-kit 플러그인

링크드인 게시글, 블로그, 사내 게시판 글처럼 **읽는 맛(리듬)이 중요한 짧은 1인칭 에세이**를 쓸 때 쓰는 플러그인입니다. Claude는 재료만 정리하고, 구성과 문장은 코덱스(ChatGPT)가 처음부터 짓습니다. 마지막에 사실과 숫자가 새지 않았는지 기계로 검사합니다.

## 왜 만들었나

report-kit의 `wording` 스킬로 링크드인 글을 만들었더니 글이 딱딱 끊기고 리듬이 없었습니다. 원인을 따져 보니 세 가지였습니다.

1. **다듬기로는 구조를 못 고칩니다.** wording은 숫자와 구조를 지키면서 문장만 고치도록 만든 도구입니다. 신청서나 보고서에는 이게 맞지만, Claude 초안이 하고 싶은 말을 하나씩 늘어놓는 구성이면 장면에서 요령으로 갑자기 넘어가는 이음새 문제가 그대로 남습니다.
2. **규칙이 끊으라고 시켰습니다.** 「문단은 짧게, 문장은 담백하게」라는 규칙을 받은 코덱스가 원래 이어져 있던 문장을 마침표로 쪼갰습니다.
   - 초안: 「질문이 하나 나왔**고**, 필터를 걸**자** 3분 동안 멈췄다.」
   - 다듬은 글: 「질문이 하나 나왔다. 필터를 걸었는데, …멈췄다.」
   그 결과 거의 모든 문장이 비슷한 길이에 「~다.」로 끝났습니다. 리듬은 긴 문장과 짧은 문장이 섞일 때 생기는데, 규칙이 그 변화를 지운 것입니다.
3. **코덱스가 생각 없이 돌았습니다.** 생각 수준(reasoning effort)이 none이어서 흐름은 따지지 않고 문장만 손봤습니다.

그래서 에세이는 역할을 뒤집었습니다. **사실은 Claude가 책임지고, 구성과 문장은 코덱스가 처음부터** 씁니다. wording 규칙에 섞지 않고 따로 둔 것은, 보고서에 필요한 「구조와 숫자를 지킨다」는 규칙과 에세이에 필요한 「구조부터 새로 짠다」는 규칙이 서로 부딪히기 때문입니다.

| | wording (report-kit) | essay (essay-kit) |
|---|---|---|
| Claude가 쓰는 것 | 완성 초안 | 재료(사실 목록)만 |
| 코덱스가 하는 일 | 문장만 다듬기(1,000자 조각) | 구성부터 전문 집필(통째로) |
| 코덱스 생각 수준 | 기본 | high |
| 검사 | 숫자, 표식이 하나라도 다르면 버림 | 필수 문구 누락, 새 숫자는 빨강, 리듬 지표 보고 |
| 고칠 때 | 다시 다듬기 | Claude가 직접 고치지 않고 고칠 점을 코덱스에 돌려보냄 |
| 맞는 글 | 보고서, 메일, 신청서 본문 | 링크드인, 블로그, 사내 게시글 |

같은 재료로 시험했을 때 결과는 이랬습니다. 스크립트가 끝 문장과 질문까지 포함한 전문으로 잰 리듬 지표입니다.

| 지표 | 기존 방식(초안+다듬기) | essay |
|---|---:|---:|
| 문장 길이 변동계수 | 0.42 | 0.45 |
| 한 문장짜리 문단 | 14개 중 4개 | 11개 중 1개 |
| 「~다.」 최장 연속 | 16 | 8 |

숫자보다 중요한 차이는 구성이었습니다. 아래에 두 글을 그대로 옮겼습니다.

## 같은 재료로 쓴 두 글

보고서 방식(Claude 초안 → wording 다듬기)으로 쓴 글과 essay로 쓴 글입니다. 링크드인에 올린 1인칭 글이며, 끝의 강의 자료 목록, 링크, 질문, 해시태그는 두 글이 같아서 뺐습니다.

| 어디가 | 보고서 방식 (wording) | essay |
|---|---|---|
| 첫 문장 | 「요즘 AI를 안 쓰는 사람은 거의 없다.」 일반론으로 시작 | 「엑셀에 필터 하나를 걸었는데 컴퓨터가 3분 동안 멈췄다.」 장면으로 시작 |
| 순서 | 예전의 나 → 바뀐 계기 → 미팅 장면 → 요령. 하고 싶은 말을 차례로 늘어놓음 | 미팅 장면 → 원시인 → 예전의 나 → 바뀐 계기 → 요령. 장면에서 고백으로 거슬러 올라감 |
| 미팅 장면 | 3문단 6문장. 「질문이 하나 나왔다. 답을 찾으려고 필터를 걸었는데」처럼 마침표로 끊김 | 2문단 4문장. 「~던 파일이었는데」「넘기자」로 이어짐 |
| 요령으로 넘어갈 때 | 「같은 엑셀을 두고도 일하는 방식에 따라 차이가 났다.」 앞 내용을 요약한 문단을 하나 더 둠 | 「그렇게 쓰면서 찾은 요령은 이렇다.」 앞 문단을 받아 바로 이음 |
| 스킬 부분 | 「다시 시킨다. 마음에 들면 …라고 한다. 그러면 …나온다.」 세 문장 | 「다시 시키고, 마음에 들면 …라고 한다. 그러면 …나온다.」 두 문장 |
| 본문 지표 | 12문단 27문장, 한 문장짜리 문단 3개, 「~다.」 최장 16번 연속 | 9문단 19문장, 한 문장짜리 문단 0개, 「~다.」 최장 6번 연속 |

### 보고서 방식 (Claude 초안 → wording)

> 요즘 AI를 안 쓰는 사람은 거의 없다. 그런데 제대로 쓰는 사람은 생각보다 드물다.
>
> 나도 그랬다. 채팅창에 묻고, 답을 복사해서 엑셀과 문서에 붙였다. 편해진 듯했지만 일은 여전히 내 손에 있었다.
>
> 불편함을 한 번 넘기고 나서 일하는 방식이 바뀌었다. VS Code를 깔고 검은 터미널 화면을 처음 봤을 때는 솔직히 무서웠다. 그래도 Claude에게 하나씩 시키다 보니 손에 익었다. 지금은 Claude가 내 컴퓨터의 파일을 직접 열고, 계산하고, 결과물까지 만든다.
>
> 최근 미팅에서 이 차이를 실감했다.
>
> 회계사분들이 공들여 만든 무거운 엑셀 파일을 가져와 자랑하듯 설명했다. 회사에서 질문이 하나 나왔다. 답을 찾으려고 필터를 걸었는데, 파일이 너무 커서 컴퓨터가 3분 동안 멈췄다.
>
> 나는 같은 질문을 Claude에게 넘겼다. Claude는 30초 만에 숫자를 뽑고, 민감도 분석까지 붙여서 보여 줬다.
>
> 솔직히 속으로 원시인 같다는 생각이 들었다. 얼마 전의 나도 똑같았으면서.
>
> 같은 엑셀을 두고도 일하는 방식에 따라 차이가 났다. 내가 찾은 요령은 이렇다.
>
> 멍청하고 무능한 팀장이 서울대 직원 부리기.
>
> 나는 멍청한 팀장처럼 말하고, AI는 엄청 똑똑하고 잘 훈련된 서울대 직원처럼 일한다. 뭐부터 시킬지, 말을 어떻게 골라야 할지 고민할 필요가 없다. 그냥 막 시키면 된다.
>
> 엉뚱한 결과가 나오면 다시 시킨다. 마음에 들면 "이거 스킬로 만들어"라고 한다. 그러면 다음부터는 처음부터 그 수준으로 나온다.
>
> 이 과정에서 겪은 시행착오를 강의 자료로 정리했다.

### essay (코덱스가 처음부터 집필, 고칠 점 1회 반영)

> 엑셀에 필터 하나를 걸었는데 컴퓨터가 3분 동안 멈췄다. 최근 미팅에서 회사가 던진 질문 하나의 답을 찾던 중이었다.
>
> 회계사분들이 공들여 만들어 와 자랑하듯 설명하던 파일이었는데, 질문에 맞춰 숫자를 보기에는 너무 무거웠다. 같은 질문을 Claude에게 넘기자 30초 만에 숫자를 뽑아 민감도 분석까지 붙여 보여 줬다.
>
> 솔직히 그때 속으로 원시인 같다는 생각이 들었다. 엑셀에 필터를 걸고 답을 기다리는 그 방식이 그랬다. 얼마 전의 나도 똑같았으면서.
>
> 나도 처음에는 채팅창에 물어보고 답을 복사해서 엑셀과 문서에 붙였다. 답을 얻는 건 편해졌는데, 그걸 가져다가 일하는 건 여전히 내 손이었다.
>
> 그러다 VS Code를 깔고 검은 터미널 화면을 처음 봤는데 무서웠다. 그래도 Claude에게 하나씩 시키다 보니 손에 익었고, 지금은 내 컴퓨터에 있는 파일을 직접 열어 계산하고 결과물까지 만들게 한다.
>
> 그렇게 쓰면서 찾은 요령은 이렇다. 멍청하고 무능한 팀장이 서울대 직원 부리기.
>
> 나는 멍청한 팀장처럼 말하고, AI는 엄청 똑똑하고 잘 훈련된 서울대 직원처럼 일한다. 뭘 먼저 시켜야 할지, 말을 어떻게 골라야 할지 고민하지 않고 그냥 막 시킨다.
>
> 엉뚱한 결과가 나오면 다시 시키고, 마음에 들면 "이거 스킬로 만들어"라고 한다. 그러면 다음부터는 처음부터 그 수준으로 나온다.
>
> 검은 화면 앞에서 시작해 이렇게 일을 맡기기까지 겪은 시행착오를 강의 자료로 정리했다. 처음 설치하고 일을 맡길 때 참고할 내용을 담았다.

보고서 방식은 숫자와 사실을 지키는 데는 강하지만, 문장을 하나씩 따로 다듬다 보니 문단 사이를 잇는 힘이 약합니다. essay는 같은 사실을 쓰면서 순서를 바꾸고 문장을 이어 붙여 읽는 흐름을 만듭니다. 그래서 보고서, 메일, 신청서는 wording으로, 사람에게 읽히는 글은 essay로 나눠 씁니다.

## 1.1.0에서 바뀐 것 (2026-10-19)

지인과 나눈 메신저 대화를 재료로 의견 에세이를 쓰다가, 첫 판이 「주제의식도 흐름도 별로」였습니다. 원인은 모두 Claude의 재료 정리였습니다. 대화를 순서대로 통째로 넣었더니 글이 대화 요약이 됐고, 구호를 맥락 없이 「그대로 넣을 것」에 넣었더니 뜬금없이 튀어나왔습니다. 「재료에 없는 건 쓰지 말라」는 규칙이 생각과 해석까지 막아 글이 얇아지기도 했습니다. 그래서 절차를 이렇게 바꿨습니다.

| 단계 | 하는 일 | 왜 |
|---|---|---|
| 0. 먼저 묻기 | 등장인물 호칭과 관계, 공개 범위, 원하는 톤 | 「선배」로 썼다가 「전 직장 동료인 형」으로 고친 일이 있어서 |
| 1. 주제 뽑기 | 원재료가 길면 코덱스가 주제 후보 6개(제목, 핵심 주장, 첫 문장, 약점)를 뽑고 사용자가 고름 (`--topics 6`) | 재료를 다 담으면 생각 하나가 서지 않음 |
| 2. 재료 만들기 | 고른 주제에 필요한 재료만, 「살을 붙여도 되는 것」 기본 | 사실은 지키고 생각은 펼치게 |
| 3. 두 판 | 사용자에게 「가장 마음에 드는 문단」을 물음 | 가장 크게 좋아진 계기 |
| 4. 핵심 문단을 정점에 | 고른 문단을 3분의 2 지점에 두고 앞 장면을 계단으로 다시 씀 | 흐름이 한 곳으로 모임 |
| 5. 이음새 진단 | Claude가 점검표로 어색한 곳을 구체적으로 짚어 돌려보냄(1~2회) | 시간이 거꾸로 감, 다리 없는 화제 전환, 이유 빠진 건너뜀, 깔아 주지 않은 구호, 어미 반복 |
| 6. 사실 대조 | 제안이 습관으로 바뀌지 않았나, 인용이 한 글자라도 바뀌지 않았나, 호칭이 맞나 | 실제로 둘 다 일어났음 |

스크립트도 바꿨습니다.

- `--topics N`으로 주제 후보를 뽑습니다.
- 재료의 「제목」, 「핵심 문단」, 「살을 붙여도 되는 것」 절을 읽습니다.
- 같은 어미가 네 번 넘게 나오거나 「~자고 했다」류가 세 번 넘게 나오면 노랑으로 표시합니다. 첫 판에서 「좋겠다.」 다섯 번, 「~자고 했다」 네 번을 잡았고 최종 판은 0건이었습니다.
- 리듬 지표(변동계수)는 등급에서 뺐습니다. 내용이 풍부해지면 문장이 길어져 수치가 내려갔는데, 읽기에는 오히려 나았습니다.
- `styles/재밌게.md`를 더했습니다. 주장은 진지하게, 말투는 가볍게 쓰되 웃음은 글쓴이 자신에게서 나오게 하고, 억지 농담이나 지어낸 일화는 쓰지 않습니다.

## 설치와 사용

```
/plugin marketplace add yangjh766-debug/report-kit
/plugin install essay-kit@report-kit
```

코덱스 CLI와 ChatGPT Plus 이상 계정이 필요합니다(`npm install -g @openai/codex`, `codex login`). 설치한 뒤 "이 경험으로 링크드인 글 써 줘"라고 하거나 `/essay-kit:essay`를 입력합니다.

## 쓰면서 알게 된 것

- **글쓴이 말투를 모아 두면 목소리가 삽니다.** 사용자가 직접 쓰거나 고친 문장을 재료의 「글쓴이 말투」 절에 원문 그대로 넣으면, 코덱스가 그 어휘와 거친 표현을 살립니다.
- **코덱스는 문단 끝에 풀이를 붙이는 버릇이 있습니다.** 「~하니 ~할 필요가 줄어든다」 같은 꼬리 문장입니다. 문체 규칙에 넣어 두었고, 그래도 남으면 고칠 점 메모로 그 문장만 빼게 합니다.
- **Claude가 직접 고치면 다시 딱딱해집니다.** 고칠 데가 있으면 `--revise`로 고칠 점만 돌려보냅니다. 시험에서 지정한 세 문장만 정확히 빠지고 나머지는 그대로 남았습니다.
- 배경으로 준 글쓴이 소개(직함 등)를 본문에 넣는 일이 있어, 재료의 「어디에 올리고 누가 읽나」 절은 본문에 쓰지 않도록 했습니다.
