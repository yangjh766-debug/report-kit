# essay-kit 플러그인

링크드인 게시글, 블로그, 사내 게시판 글처럼 **읽는 맛(리듬)이 중요한 짧은 1인칭 에세이**를 쓸 때 쓰는 플러그인입니다. Claude는 재료만 정리하고, 구성과 문장은 코덱스(ChatGPT)가 처음부터 짓습니다. 마지막에 사실과 숫자가 새지 않았는지 기계로 검사합니다.

## 왜 만들었나

report-kit의 `wording` 스킬로 링크드인 글을 만들었더니 글이 딱딱 끊기고 리듬이 없었습니다. 원인을 따져 보니 세 가지였습니다.

1. **다듬기로는 구조를 못 고칩니다.** wording은 숫자와 구조를 지키면서 문장만 고치도록 만든 도구입니다. 신청서나 보고서에는 이게 맞지만, Claude 초안이 하고 싶은 말을 하나씩 늘어놓는 구성이면 장면에서 요령으로 갑자기 넘어가는 이음새 문제가 그대로 남습니다.
2. **규칙이 끊으라고 시켰습니다.** 「문단은 짧게, 문장은 담백하게」라는 규칙을 받은 코덱스가 원래 이어져 있던 문장을 마침표로 쪼갰습니다.
   - 초안: 「질문이 하나 나왔**고**, 필터를 걸**자** 3분 동안 멈췄다.」
   - 다듬은 글: 「질문이 하나 나왔다. 필터를 걸었는데, …멈췄다.」
   그 결과 거의 모든 문장이 비슷한 길이에 「~다.」로 끝났습니다. 리듬은 긴 문장과 짧은 문장이 섞일 때 생기는데, 규칙이 그 변화를 지운 것입니다.
3. **코덱스가 생각 없이 돌았습니다.** 생각 수준(reasoning effort)이 none이어서 흐름은 따지지 않고 문장만 손봤습니다.

그래서 에세이는 역할을 뒤집었습니다. **사실은 Claude가 책임지고, 구성과 문장은 코덱스가 처음부터** 씁니다. wording 규칙에 섞지 않고 따로 둔 것은, 보고서에 필요한 「구조와 숫자를 지킨다」는 규칙과 에세이에 필요한 「구조부터 새로 짠다」는 규칙이 서로 부딪히기 때문입니다.

| | wording (report-kit) | essay (essay-kit) |
|---|---|---|
| Claude가 쓰는 것 | 완성 초안 | 재료(사실 목록)만 |
| 코덱스가 하는 일 | 문장만 다듬기(1,000자 조각) | 구성부터 전문 집필(통째로) |
| 코덱스 생각 수준 | 기본 | high |
| 검사 | 숫자, 표식이 하나라도 다르면 버림 | 필수 문구 누락, 새 숫자는 빨강, 리듬 지표 보고 |
| 고칠 때 | 다시 다듬기 | Claude가 직접 고치지 않고 고칠 점을 코덱스에 돌려보냄 |
| 맞는 글 | 보고서, 메일, 신청서 본문 | 링크드인, 블로그, 사내 게시글 |

같은 재료로 시험했을 때 결과는 이랬습니다(리듬 지표는 스크립트가 자동으로 잽니다).

| 지표 | 기존 방식(초안+다듬기) | essay |
|---|---:|---:|
| 문장 길이 변동계수 | 0.42 | 0.45 |
| 한 문장짜리 문단 | 14개 중 4개 | 11개 중 1개 |
| 「~다.」 최장 연속 | 16 | 8 |

숫자보다 중요한 차이는 구성이었습니다. 기존 글은 「요즘 AI를 안 쓰는 사람은 거의 없다」는 일반론으로 시작했는데, essay 판은 「엑셀에 필터 하나를 걸었는데 컴퓨터가 3분 동안 멈췄다」는 장면으로 시작했습니다.

## 들어 있는 것

| 파일 | 하는 일 |
|---|---|
| `skills/essay/SKILL.md` | 절차: 재료 정리 → 코덱스 집필(두 판) → 검사 → 고칠 점 돌려보내기 |
| `skills/essay/brief_template.md` | 재료 양식. 사실, 숫자, 그대로 넣을 것, 글쓴이 말투, 하지 말 것, 분량 |
| `skills/essay/styles/linkedin.md` | 문체 규칙. 리듬(문장 길이 섞기, 이어 쓰기), 구성(장면 먼저, 이음 문장), 금지 표현 |
| `skills/essay/write.py` | 코덱스 호출과 검사. 필수 문구 누락, 재료에 없는 숫자, 금지 표현, 리듬 지표를 보고서로 |

## 설치와 사용

```
/plugin marketplace add yangjh766-debug/report-kit
/plugin install essay-kit@report-kit
```

코덱스 CLI와 ChatGPT Plus 이상 계정이 필요합니다(`npm install -g @openai/codex`, `codex login`). 설치한 뒤 "이 경험으로 링크드인 글 써 줘"라고 하거나 `/essay-kit:essay`를 입력합니다.

## 쓰면서 알게 된 것

- **글쓴이 말투를 모아 두면 목소리가 삽니다.** 사용자가 직접 쓰거나 고친 문장을 재료의 「글쓴이 말투」 절에 원문 그대로 넣으면, 코덱스가 그 어휘와 거친 표현을 살립니다.
- **코덱스는 문단 끝에 풀이를 붙이는 버릇이 있습니다.** 「~하니 ~할 필요가 줄어든다」 같은 꼬리 문장입니다. 문체 규칙에 넣어 두었고, 그래도 남으면 고칠 점 메모로 그 문장만 빼게 합니다.
- **Claude가 직접 고치면 다시 딱딱해집니다.** 고칠 데가 있으면 `--revise`로 고칠 점만 돌려보냅니다. 시험에서 지정한 세 문장만 정확히 빠지고 나머지는 그대로 남았습니다.
- 배경으로 준 글쓴이 소개(직함 등)를 본문에 넣는 일이 있어, 재료의 「어디에 올리고 누가 읽나」 절은 본문에 쓰지 않도록 했습니다.
