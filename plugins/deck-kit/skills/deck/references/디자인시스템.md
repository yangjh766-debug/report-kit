# 디자인 시스템

모든 값은 `deck_lib.js`에 들어 있다. 회사 색을 쓰려면 `accent`(강조색), `accentSoft`(연한 강조), `accentLine`(중간 강조)만 바꾼다.

## 1. 토큰

| 이름 | 값 | 쓰임 |
|---|---|---|
| ink | 141414 | 제목, 기준 막대, 진한 선 |
| text | 2B2B2B | 본문 |
| sub | 6B6B6B | 부제, 설명 |
| mute | 9E9B96 | 라벨, 각주 |
| hair | D9D6D1 | 얇은 구분선 |
| paper | F4F2EE | 강조 상자 바탕 |
| stone | CFCBC4 | 과거 실적, 보조 막대 |
| accent | 회사 색(기본 FF4438) | 한 장에 한두 곳만: 가장 중요한 숫자, 막대, 단계 |
| night | 0B0B0B | 핵심 장표 바탕 |

- 글꼴: Pretendard. 큰 숫자와 핵심 문구는 Pretendard ExtraBold.
- 글자 크기: 장 제목 25pt, 부제 12.5pt, 본문 9.5~11pt, 각주 7.5pt, 핵심 숫자 30~44pt, 핵심 장표 숫자 150~200pt.
- 화면: 16:9(13.333 × 7.5in), 좌우 여백 0.6in, 12단 그리드(단 사이 0.2in). `gx(단)`, `span(단 수)`로 위치를 잡는다.

## 2. 장 유형 (엔진 함수)

| 함수 | 장 |
|---|---|
| `cover`, `closing` | 표지, 맺음(검은 화면, 빛 번짐) |
| `summary` | 한 장 요약(왼쪽 결론, 오른쪽 숫자 셋) |
| `heroNumber` | 숫자 하나. `morph` 이름을 다음 장 차트와 맞추면 모핑 |
| `heroPhoto` | 전면 사진 + 왼쪽 글자. `make_assets.py darken`으로 미리 어둡게 한 사진이면 `darkened: true` |
| `heroQuote` | 한 문장 |
| `content` | 증거 장 틀(섹션 표시, 제목, 부제, 각주, 쪽번호). 반환된 장에 아래 요소를 얹는다 |
| `trend` | 추이 막대(과거 회색, 기준 검정, 전망 점선, 계획 강조색) + 보조 지표 줄 |
| `bridge` | 다리형 증감 분해, 계획선 선택 |
| `kpis` | 핵심 지표 가로 줄 |
| `planRows` | 계획 대비 구성 막대(좁은 칸 이름은 자동으로 범례로) |
| `barsH` | 가로 막대 비교(배수 등) |
| `shareBars` | 100% 구성 막대(지분율 전후 등) |
| `strip` | 100% 가로 띠(자금 사용 등) |
| `timeline` | 연혁 |
| `chevrons` | 가치사슬, 단계 띠 |
| `cards` | 번호 카드 격자(같은 크기). 남는 칸에 강조 상자 |
| `callout` | 강조 상자 |
| `pipeline` | 단계별 카드(사진 또는 로고) + 빈칸 강조 상자 |
| `table` | 얇은 선 표 |
| `iconRow` | 아이콘 줄(assets/icons) |
| `photoRow` | 사진 카드 줄(같은 비율 칸) |

## 3. 사진

- 원본 비율을 지킨다. 칸과 비율이 달라 20% 넘게 잘리면 엔진이 경고한다. 세로 사진은 세로 칸, 정사각 사진은 정사각 칸.
- 맞는 사진이 없으면 사진을 빼고 숫자나 도형으로 짠다.
- 로고는 자르지 않는다(`img(..., contain=true)`).
- 사람 얼굴, 공연 사진, 남의 저작물은 사용 권한을 확인한다.

## 4. 레이아웃 규칙

- 같은 줄, 같은 묶음의 칸은 같은 크기(위 4칸 아래 3칸처럼 섞지 않음). 남는 칸은 강조 상자로 채운다.
- 강조색은 한 장에 한두 곳. 나머지는 먹색과 회색.
- 선은 얇게(0.75~1pt). 상자와 그림자는 쓰지 않고 선과 여백으로 나눈다.
- 각주는 7.0in 선 아래 두 줄 이내.

## 5. 점검 순서

1. `node build.js`: 사진 잘림 검사 0건
2. `finalize.py`: 어절 단위 줄바꿈, 전환
3. `check_text.py`: 단어 끊김, 외톨이 줄, 넘침 0건
4. `render_preview.sh`: 그림으로 겹침, 빈 공간, 칸 크기 확인
5. PowerPoint에서 최종 확인(모핑은 PowerPoint 슬라이드쇼에서만 보인다)
