# 개선 루프

전략 → 실행 → 검토(채점) → 목표 점수 미달이면 다시. 이 순서를 정해진 라운드 안에서 되풀이한다.
메인 대화(너)는 진행만 맡는다. 계획, 실행, 채점은 각각 strategist, executor, reviewer 에이전트에게 맡기고 직접 하지 않는다.

## 0. 시작 전에 사용자와 정할 것

아래 다섯 가지를 정해 `.loop/<작업이름>/`에 저장한다. 사용자가 말하지 않은 것은 기본값을 제안하고 한 번에 확인받는다.

| 항목 | 파일 | 기본값 |
|---|---|---|
| 목표, 독자, 결과물 형식과 저장 위치 | goal.md | 요청에서 정리 |
| 채점 기준표(기준 4~6개, 배점 합계 100, 기준마다 만점 조건) | rubric.md | 아래 예시를 고쳐 씀 |
| 목표 점수 | state.json의 target | 90 |
| 최대 라운드 | state.json의 max_rounds | 4 |
| 라운드 사이에 사람 확인을 받을지 | state.json의 human_check | false |

채점 기준표 예시(보고서):
```markdown
| 기준 | 배점 | 만점 조건 |
|---|---|---|
| 숫자 정확성 | 30 | 모든 숫자가 원천과 일치하고 근거 위치가 있다 |
| 목적 달성 | 25 | 독자가 결정할 사항과 근거가 첫 쪽에 있다 |
| 구성 | 15 | 결론 먼저, 현황, 원인, 대응 순서가 분명하다 |
| 문장 | 15 | 금지 표현 0건, 번역투 없음, 한 문단 3~5문장 |
| 표와 서식 | 15 | 단위, 제목, 정렬 규칙을 지키고 잘린 칸이 없다 |
```

상태 파일은 프로젝트 폴더의 `.loop/state.json` 하나다(동시에 루프 하나만 돈다).
```json
{"task": "작업이름", "status": "running", "round": 0, "score": 0, "target": 90, "max_rounds": 4, "human_check": false, "history": []}
```

## 1. 라운드 진행 (round = N)

1. state.json의 round를 N으로 올린다.
2. **strategist**에게 맡긴다: 작업 폴더 경로, 라운드 번호, 직전 review.json 경로(있으면). 결과는 `round-N/plan.md`.
3. **executor**에게 맡긴다: plan.md 경로. 결과물과 `round-N/exec-notes.md`.
4. **reviewer**에게 맡긴다: goal.md, rubric.md, 결과물 경로, 목표 점수. 결과는 `round-N/review.json`.
5. review.json을 읽어 state.json의 score를 갱신하고 history에 `{"round": N, "score": 점수}`를 덧붙인다.
6. 사용자에게 한 줄로 알린다: `라운드 N: 78점(목표 90). 감점 큰 곳: 숫자 정확성 -8, 문장 -6`

## 2. 다음으로 넘어갈지 판단

- score ≥ target: status를 "done"으로 바꾸고 끝낸다.
- round = max_rounds: status를 "stopped"로 바꾸고, 남은 감점 사유와 사람이 판단할 것을 보고한 뒤 멈춘다.
- 두 라운드 연속 점수가 오르지 않음: status를 "stalled"로 바꾸고 멈춘다. 기준표나 목표가 맞는지 사용자에게 묻는다.
- human_check가 true: status를 "paused"로 바꾸고 점수와 결과물을 보여 준 뒤 사용자의 "계속"을 기다린다.
- 그 밖에는 바로 다음 라운드로 간다. 사용자에게 계속할지 묻지 않는다.

플러그인의 종료 관문 훅은 status가 "running"인데 목표 점수와 최대 라운드 어느 쪽에도 닿지 않은 채 끝내려 하면 끝내지 못하게 하고 다음 라운드를 하라고 알려 준다. 루프를 멈춰야 할 이유가 있으면 status를 "paused"나 "stopped"로 바꾼 뒤 멈춘다.

## 3. 끝났을 때 보고

- 최종 점수와 라운드별 점수 흐름(예: 62 → 78 → 91)
- 최종 결과물 경로
- 검토 담당이 마지막에 남긴 must_fix 중 남은 것
- 사람이 직접 확인할 것([확인 필요] 표식, 숫자 근거)

## 지킬 것

- 채점 기준은 루프 도중에 바꾸지 않는다. 바꿔야 하면 멈추고 사용자와 다시 정한 뒤 round를 0부터 시작한다.
- 검토는 반드시 reviewer 에이전트가 한다. 메인 대화나 executor가 스스로 점수를 매기지 않는다.
- 라운드마다 결과물을 `round-N/`에 남겨 어느 라운드로든 되돌릴 수 있게 한다.
- 밖으로 나가는 일(메일 발송, 업로드, 결제)은 루프 안에서 하지 않는다. 끝난 뒤 사용자가 한다.
- 비용: 라운드마다 에이전트 셋이 돈다. 큰 작업은 max_rounds를 3~4로 둔다.
