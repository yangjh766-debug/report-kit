# 보고서 작성

숫자가 틀리지 않고, AI가 쓴 티가 나지 않고, 표와 문서 모양이 실무 전문가의 검토보고서처럼 보이는 Word를 만든다.

## 먼저 확인: 이 스킬을 쓰지 않는 경우

- 프로젝트 CLAUDE.md나 지침 폴더가 문서 양식을 정해 두었으면 그 양식이 우선이다. 이 스킬의 양식을 섞지 않는다.
- 상장예비심사신청서, 증권신고서, 공시 서류처럼 제출 서식이 정해진 문서는 그 서식 전용 지침을 따른다.

## 규칙 파일 (`${CLAUDE_PLUGIN_ROOT}/skills/report/references/`)

| 파일 | 언제 |
|---|---|
| `워딩규칙.md` | 항상. 숫자 원칙, AI 티 제거, 표식 |
| `문체_검토보고.md` | 내부 검토자료, 보고서, 메모(기본값) |
| `문체_서술형.md` | 대외 서신, 투자자 안내문, 메일 |
| `표서식규칙.md` | 표가 있을 때 |

## 절차

1. **문서 종류와 양식을 정한다.**
   - 독자와 목적을 보고 문체를 고른다. 내부용이면 검토보고, 밖으로 나가는 글이면 서술형. 애매하면 검토보고로 쓰고 첫 줄에 적어 확인받는다.
   - 사용자가 기존 자료(docx)를 주면 그 양식을 먼저 잰다. 여백, 글꼴 크기, 절 제목 선, 표 괘선과 음영, 열 정렬, 머리글을 뽑아 준다. 기본값과 다르면 그 값을 따른다.
     ```bash
     python3 "${CLAUDE_PLUGIN_ROOT}/skills/report/scripts/docx_spec.py" 기존자료.docx
     ```
     PDF만 있으면 첫 두 쪽을 그림으로 보고 같은 항목을 확인한다.

2. **숫자부터 확인한다.** 쓸 숫자를 원천(엑셀, PDF, 메일)에서 찾아 작업 원고에 `(출처: 파일 p.N)`으로 붙인다. 원천에 없으면 만들지 않고 `[확인 필요: 무엇]`으로 둔다.

3. **마크다운 원고를 쓴다.** 고른 문체 파일의 구성과 문장 규칙을 따른다. 검토보고 원고의 뼈대:
   ```markdown
   # 문서 제목
   > 검토 범위를 쉼표로

   ## Ⅰ. 검토 개요
   - 배경과 목적을 개조식으로 적음.
   - (판정 기준) 핵심 기준을 __밑줄__로 강조함(근거 법령 제○조).

   [의뢰 내용 정리]
   | No. | 구분 | 내용 |
   |---|---|---|
   | 1 | 배경 | … |

   ## Ⅹ. 종합의견
   - 결론과 권고를 적음.

   주) 본 자료는 내부 검토를 위한 참고자료임. 세부사항은 법률 및 회계 자문을 통해 확인할 필요가 있음.
   ```
   - 표 위 `[제목]`은 `[표 N] 제목`으로, 그림 위 `[제목]`은 `[그림 N] 제목`으로 번호가 붙는다. 숫자 표는 `(단위: 백만원)` 줄을 제목 아래에 둔다.
   - 표 합계는 `**굵게**`, 음수는 `(1,234)`, 0은 `-`. 본문 강조는 `__밑줄__`만.
   - 그림(흐름도, 구조도)은 PNG로 만들어 `![제목](경로)`로 넣는다.

4. **스스로 점검한다.** 저장하면 플러그인 훅이 금지 표현, 굵게 남용, 문체 섞임을 찾아 알려 준다. 알림이 오면 고친다. 따로 돌릴 때:
   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/doc_check.py" 원고.md
   ```

5. **문장을 다듬는다(선택).** 외부로 나가거나 사용자가 원하면 wording 스킬로 코덱스에게 맡긴다. 이때 고른 문체 파일을 함께 넘긴다. 코덱스가 없으면 건너뛰고 알린다.

6. **Word로 만든다.**
   ```bash
   S="${CLAUDE_PLUGIN_ROOT}/skills/report/scripts"
   # 검토보고(기본)
   python3 "$S/md2docx_table.py" 원고.md 결과.docx --look review "--header=내부 검토자료 │ Strictly Confidential"
   # 서술형 문서나 표만 필요한 문서
   python3 "$S/md2docx_table.py" 원고.md 결과.docx
   ```
   끝에 「원천 표기 잔존 0건」, 「기본 정보 접힘 0건」이 나와야 한다. 머리글 문구는 문서 성격에 맞게 바꾼다(예: 「이사회 보고자료」).

7. **눈으로 확인한다.**
   ```bash
   python3 "$S/table_render.py" 결과.docx 렌더폴더          # 표를 실제 열 폭과 글자 크기로 그림
   qlmanage -t -s 1400 -o 렌더폴더 결과.docx >/dev/null      # 첫 쪽 전체 모양(맥 미리보기. 표 폭은 실제와 다르게 보임)
   ```
   그림을 직접 열어 잘린 숫자, 접힌 이름, 쪽 구성을 본다. Word를 스크립트로 조작해 PDF를 만들지 않는다(사용자가 열어 둔 다른 문서를 건드릴 수 있다).

8. **보고한다.** 만든 파일 경로, 그대로 둔 것, 사용자가 판단하거나 채울 것(노란 칸 목록). 실수가 있었으면 맨 앞에 말한다.

## 사용자가 Word에서 직접 고친 뒤

그 파일이 새 원본이다. 마크다운에서 다시 만들지 않는다. 지시받은 칸과 문단만 python-docx로 직접 고치고, 바꾼 곳마다 전후 글자를 나란히 보여 준다.

## 하지 않는 것

- 원본에 없는 숫자, 사실, 전망을 만들지 않는다.
- 폭이 모자란다고 표 글자부터 줄이지 않는다(표서식규칙의 순서).
- 흑백과 회색 외의 색을 쓰지 않는다. 노란 형광은 사용자가 확인할 곳에만.
- 메일 발송, 업로드처럼 밖으로 나가는 일은 사용자 확인 없이 하지 않는다.
