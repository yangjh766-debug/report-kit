# 문체: 검토보고 (개조식 실무체)

내부 검토자료, 경영 보고, 투자 검토, 법률과 세무 쟁점 정리, 회의 자료에 쓴다.
한국 기업 실무자가 쓴 검토보고서처럼 짧고 단정한 개조식으로 쓴다.

## 1. 문서 구성

```
# 문서 제목                         ← 가운데, 아래 이중선
> 부제(검토 범위를 쉼표로)            ← 가운데
## Ⅰ. 검토 개요                     ← 배경, 목적, 검토 범위(① ② ③)
   [의뢰 내용 정리] 표(No. | 구분 | 내용)
## Ⅱ. ~ Ⅸ. 본론                    ← 쟁점, 현행 구조, 검토, 리스크, 대안, 필요 서류, 사례
## Ⅹ. 종합의견(및 대응방안)          ← 마지막 절은 항상 종합의견
주) 본 자료는 내부 검토를 위한 참고자료임. 세부사항은 법률 및 회계 자문을 통해 확인할 필요가 있음.
```

- 절 제목은 로마숫자(Ⅰ. Ⅱ. Ⅲ.)를 직접 쓴다. 절 안의 소제목은 `[1. 사례 A: ○○]`처럼 대괄호로 쓰면 굵은 가운데 소제목이 된다.
- 표는 `[표 제목]` 한 줄을 표 위에 두면 변환할 때 `[표 N] 제목`으로 번호가 붙는다. 그림도 같다(`[그림 N]`).
- 쟁점이 여럿이면 표로 정리한다: 쟁점 질문 표(No. | 쟁점 질문 | 확인 사항 및 검토 방향), 리스크 표(구분 | 내용 | 근거 | 수준), 대안 비교 표(구분 | 구조 | 효과 | 유의사항), 필요 서류 표(서류 | 주요 내용 | 비고).
- 면책은 장문 문단으로 쓰지 않고 마지막에 주) 한 줄로 둔다.

## 2. 문장

- 본문은 대시(-) 항목으로 쓴다. 한 항목은 한두 문장.
- 어미는 「~임」, 「~함」, 「~됨」, 「~필요가 있음」, 「~요구됨」, 「~바람직함」, 「~로 판단됨」, 「~로 예상됨」. 서술식(「~습니다」)과 섞지 않는다.
- 항목 앞에 괄호 라벨을 붙이면 읽기 쉽다: (판정 기준) (위험요인) (대응방안) (선례) (권고) (현행) (제안).
- 나열은 ① ② ③ 또는 쉼표. 가운뎃점은 쓰지 않는다.
- 법령과 근거는 문장 끝 괄호로: (약사법 제20조), (공시규정 제7조).
- 강조는 밑줄(`__핵심 워딩__`)로 한 절에 1~3곳만. 대상: 기한과 판정 기준, 결론적 판단, 대응방안의 첫 수단.

## 3. 설명체를 검토보고체로

| 설명체 | 검토보고체 |
|---|---|
| ~해야 한다, ~할 것 | ~할 필요가 있음, ~이 요구됨 |
| ~된다, ~이다 | ~됨, ~임 |
| ~로 보인다 | ~로 판단됨, ~로 예상됨 |
| 위반된다 | 저촉됨 |
| 설명하지 못하면 | 소명하지 못하는 경우 |
| 준비해야 한다 | 사전에 구비할 필요가 있음 |
| 위험이 있다 | 위험이 상존함 |
| 반드시 피해야 한다 | 회피하는 것이 바람직함 |

자주 쓰는 실무 어휘: 적기 이행, 명문화, 상회, 하회, ~에 비추어, ~하는 바, 선결적으로, 소명, 실질, 정상가격.

---

## 코덱스에게 전달할 규칙

- 내부 검토보고서 문체로 쓴다. 본문은 대시(-) 개조식 항목이고, 어미는 "~임", "~함", "~됨", "~필요가 있음", "~요구됨", "~로 판단됨"으로 끝낸다.
- "~습니다", "~입니다" 같은 서술식 어미로 바꾸지 않는다. 개조식을 서술식 문단으로 풀지 않는다.
- 대시 항목의 개수와 순서를 유지한다. 한 항목은 한두 문장으로 짧게 쓴다.
- 항목 앞의 괄호 라벨((판정 기준), (대응방안) 등)과 ① ② ③ 번호는 그대로 둔다.
- __밑줄__ 표시는 그 글자 그대로 두고 새로 만들지 않는다.
- "~해야 한다"는 "~할 필요가 있음"으로, "~로 보인다"는 "~로 판단됨"으로 바꾸는 식의 실무 어휘를 쓴다.
