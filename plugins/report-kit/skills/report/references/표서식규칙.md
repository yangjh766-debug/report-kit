# 표 서식 규칙 (Word와 엑셀)

AI가 만든 표가 "밋밋하거나 어색하게" 나오지 않도록 정한 규칙이다. 숫자 검증은 끝났다고 보고, 그 숫자를 어떻게 보여 줄지만 다룬다.
Word 표는 `4_도구/표서식엔진/md2docx_표엔진.py`가 아래 규칙 대부분을 자동으로 적용한다.

---

## 1. 마크다운으로 표를 쓰는 법 (변환기 입력 규칙)

```markdown
당사의 3분기 월별 실적은 다음과 같습니다.

[월별 손익]
(단위: 백만원)

| 구분 | 7월 | 8월 | 합계 |
|---|---|---|---|
| 매출액 | 1,234 | 1,456 | **2,690** |
| 영업이익 | 120 | (35) | **85** |

주1) 8월은 가결산 기준입니다.
```

- 표 위에 안내 문장 한 줄, `[표 제목]` 줄, `(단위: …)` 줄을 둔다.
- 합계와 소계는 `**굵게**`로 직접 쓴다.
- 음수는 괄호 `(35)`로 쓴다. 그래야 숫자 열로 인식되어 오른쪽 정렬된다.
- 칸에 `^`만 쓰면 위 칸과 세로 병합, `<`만 쓰면 왼쪽 칸과 가로 병합이다. 2단 머리행에 쓴다.
- 칸 안 줄바꿈은 `<br>`. 의미 단위로 나눈다(「대표이사<br>(등기)」).
- `[확인 필요: …]`, `##`는 노란 형광, `[메모: …]`는 Word 메모가 된다.
- 머리행이 「출처」, 「근거」인 열은 docx에서 자동으로 빠진다. 작업 원고에만 출처를 둔다.

변환과 확인:
```bash
python3 md2docx_표엔진.py 문서.md 문서.docx     # 끝에 '원천 표기 잔존 0건', '접힘 0건'이 나와야 한다
python3 표렌더.py 문서.docx 렌더폴더              # 표를 PNG로 그려 눈으로 확인
```

## 2. Word 표 규칙

| # | 규칙 | 이유 |
|---|---|---|
| 1 | 머리행은 회색 `D9D9D9`, 굵게, 가운데 | 표마다 같은 모양이어야 머리글이 한눈에 구분된다 |
| 2 | 글꼴 맑은 고딕, 표 9pt, 본문 10pt. 한 표 안 글자 크기는 모두 같게 | 한 칸만 작으면 실수로 보인다 |
| 3 | 줄간격 1.0, 문단 앞뒤 간격 0 | 행 높이가 들쭉날쭉하지 않게 |
| 4 | 정렬은 **열 단위로 통일**. 숫자 오른쪽, 날짜와 짧은 글 가운데, 긴 글 왼쪽 | 한 열 안에서 정렬이 섞이면 지저분하다 |
| 5 | 판정은 **날짜를 숫자보다 먼저** 본다 | `2026.09.30`이 숫자로 판정되면 오른쪽에 붙는다 |
| 6 | 열 폭은 균등 분할하지 않고 실제 글자 폭을 재서 배분 | 이름은 접히고 긴 칸은 남는 일을 막는다 |
| 7 | **글자 크기는 최후의 수단.** 폭 재배분 → 병합, 주석으로 빼기 → 의미 단위 줄바꿈 → 셀 여백 → 0.5pt씩 축소(하한 6.5pt, 축소하면 보고) | 「잘 보이게 해 줘」에 글자를 줄이는 것은 정반대 행동이다 |
| 8 | 숫자: 천 단위 쉼표, 음수 괄호 `(1,234)`, 비율 소수 둘째 자리 `12.34%` | 「△」, 「-1,234」는 쓰지 않는다 |
| 9 | 표 안 0은 「-」 | 0이 많으면 의미 있는 숫자가 묻힌다 |
| 10 | 연도 열은 오래된 연도부터 왼쪽에서 오른쪽 | 최근 연도가 맨 오른쪽 |
| 11 | 같은 주체의 반복 값만 세로 병합. 「상동」은 쓰지 않는다 | 숫자, 「-」는 같아도 합치지 않는다 |
| 12 | 비고 칸은 짧은 명사구만. 문장이 되면 `주1)`로 표 아래에 뺀다 | 비고가 길면 다른 열 폭을 빼앗는다 |
| 13 | 주석은 표 바로 아래, 들여쓰기 없이, 한 주석에 한 사실 | 어느 표의 설명인지 헷갈리지 않게 |
| 14 | 열이 15개를 넘으면 의미 단위로 표를 둘로 나눈다 | 글자를 줄여도 읽기 어렵다 |
| 15 | 해당 사항이 없으면 빈 표 대신 한 문장 | 빈 표는 누락처럼 보인다 |
| 16 | 열이 9개 이상이면 날짜를 `YY.MM.DD`로 | 「20」 두 글자만큼 다른 열에 폭이 돌아간다 |

## 2-1. 검토보고 모양 (`--look review`)

내부 검토자료에 쓰는 회색톤 양식이다. 변환기가 아래를 자동으로 적용한다.

| 요소 | 규격 |
|---|---|
| 쪽 | A4, 사방 여백 2cm(표 폭 합계 9,638twips) |
| 문서 제목 | 15pt 굵게 가운데, 아래 `> 부제` 10pt 가운데, 그 아래 이중선 |
| 절 제목 | `## Ⅰ. 제목` 11pt 굵게, 아래 회색(808080) 실선, 앞 16pt 뒤 8pt |
| 본문 | 10pt 양쪽 정렬, 줄간격 1.25, 대시(-) 항목은 내어쓰기 |
| 표 | 위아래 이중괘선, 안쪽 가는 실선, 머리행 회색 D9D9D9 굵게 가운데, 쪽이 넘어가면 머리행 반복 |
| 표 정렬 | 첫 열(No., 구분)과 날짜 열은 가운데, 글 열은 왼쪽, 숫자 열은 오른쪽 |
| 셀 여백 | 위아래 40twips, 좌우 80twips |
| 캡션 | 표와 그림 위 가운데 `[표 N] 제목`, `[그림 N] 제목`(번호 자동), 굵게 안 함 |
| 소제목 | 표나 그림이 뒤따르지 않는 `[1. 사례 A: 제목]`은 굵은 가운데 소제목 |
| 각주 | 표 아래 `주1)` 9pt, 문서 끝 면책 `주)` 한 줄 |
| 머리글, 바닥글 | 오른쪽 위 회색 8pt 문구(예: 내부 검토자료 │ Strictly Confidential), 가운데 아래 `- 쪽번호 -` |
| 색 | 흑백과 회색만. 노란 형광은 사용자가 확인할 곳에만 |

자주 쓰는 표 틀:
- 의뢰 내용 정리: No. | 구분 | 내용
- 쟁점: No. | 쟁점 질문 | 확인 사항 및 검토 방향
- 리스크: 구분 | 내용 | 근거 | 수준
- 대안 비교: 구분 | 구조 | 효과 | 유의사항
- 필요 서류: 서류 | 주요 내용 | 비고
- 사례 비교: 구분 | 주체 | 구조 | 대가의 성격 | 판단 요소 | 본건과의 차이

회사 양식이 따로 있으면 `docx_spec.py 기존자료.docx`로 재서 다른 값만 맞춘다.

## 3. 엑셀 (외부 제출용)

- Arial 9, 머리글 회색(D9D9D9) 검정 굵게, 소계 연회색(F2F2F2), 숫자 회계 서식 `_-* #,##0_-`.
- 제목은 A1에 `[제목]`, 단위는 제목 아래 줄.
- 강조색(노랑, 파랑, 남색)과 긴 설명 주석 금지. 사람이 만든 파일처럼 보여야 한다.
- 숫자는 가능하면 하드코딩 대신 원천 시트를 참조하는 수식(SUMIFS 등)으로 둔다. 받은 사람이 검증할 수 있다.
- 내부 검증 시트, 확인 메모는 떼어 별도 파일로.
- 만든 뒤 엑셀에서 한 번 열어 재계산되는지 확인한다(없는 시트를 가리키는 수식이 하나라도 있으면 엑셀이 파일을 조용히 거부한다).

## 4. 자주 하는 실수

- 가진 자료에 맞춰 열을 새로 만들거나, 자료 없는 열을 지운다. → 열은 그대로 두고 「-」이나 표식으로 채운다.
- 폭이 모자라자 바로 8pt, 7pt로 줄인다.
- Word 자동 줄바꿈에 맡겨 「1,234,5 / 67」처럼 숫자가 잘린다.
- 사용자가 Word에서 고친 파일을 마크다운에서 다시 만들어, 지운 내용이 되살아난다. → 사용자가 손댄 파일이 그때부터 원본이다.

## 5. 넘기기 전 점검표

- [ ] 표 위 안내 문장, `[제목]`, `(단위: …)`가 있다
- [ ] 머리행 모두 회색, 굵게, 가운데
- [ ] 열마다 정렬이 하나다
- [ ] 숫자, 날짜가 잘리거나 이름이 접힌 칸이 없다(표렌더 PNG로 확인)
- [ ] 0은 「-」, 음수는 괄호
- [ ] 가운뎃점 0건, 출처 표기 0건
- [ ] 노란 표식이 남아 있다면 받는 사람이 채울 곳뿐이다
