# 워딩 다듬기 (코덱스에게 맡기기)

내용, 구조, 숫자는 Claude가 책임지고, 문장을 자연스럽게 다시 쓰는 일만 코덱스(OpenAI Codex CLI)에게 맡긴다.

## 규칙

- 숫자, 날짜, 금액, 비율, 고유명사는 하나도 바뀌면 안 된다. 하나라도 다르면 그 결과는 쓰지 않는다.
- 분량은 자유다. 코덱스가 문장을 늘리거나 줄이거나 합쳐도 된다.
- 제목, 표, 논리 순서는 그대로 둔다.
- 원본 파일은 사용자가 "적용해 줘"라고 할 때만 덮어쓴다.

## 준비 확인

```bash
export PATH="$HOME/.local/node/bin:$HOME/.npm-global/bin:/opt/homebrew/bin:$PATH"
codex --version && codex login status
```
- `codex`가 없으면: `npm install -g @openai/codex` 후 `codex login`을 사용자에게 안내한다(node가 필요하다).
- 로그인이 안 됐으면 사용자에게 터미널에서 `codex login`을 직접 치게 한다. 브라우저가 열리면 ChatGPT 계정으로 승인한다.
- 코덱스 호출마다 사용자의 ChatGPT 사용량이 쓰인다(3쪽 글 약 1만 토큰). 처음 쓰는 사용자에게 한 번 알린다.

## 절차

1. 다듬을 글을 정한다. 인자로 파일 경로가 오면 그 파일, 없으면 직전에 Claude가 쓴 글.
2. 글을 작업 폴더(scratchpad 등)에 `wording_draft.md`로 저장한다. 코덱스는 현재 폴더 밖 파일을 읽지 못한다.
3. 조각 수와 예상 시간(조각당 1분 안팎)을 먼저 알린다. 5쪽 이하 1~2분, 10쪽 3~4분.
4. 백그라운드로 실행한다.

```bash
cd <작업 폴더>
python3 "${CLAUDE_PLUGIN_ROOT}/skills/wording/polish.py" wording_draft.md wording_polished.md \
  --jobs 3 --style "${CLAUDE_PLUGIN_ROOT}/skills/report/references/워딩규칙.md" > polish.log 2>&1
# 프로젝트 전용 용어집이 있으면 --style 을 더 붙인다(여러 번 가능)
```
   사용자가 진행 상황을 보고 싶어 하면 `tail -f <작업 폴더>/polish.log`를 알려 준다.

5. `wording_polished.report.md`의 등급을 먼저 본다.
   - 녹색: 결과를 보여 주고 달라진 부분을 두세 줄로 짚는다.
   - 노랑: 제목 구성이 바뀐 것이니 결과와 함께 그 점을 알린다.
   - 빨강: 숫자가 다르다. 결과를 쓰지 않는다. `--chunk 500`으로 그 조각만 다시 돌리거나 원문을 유지하고 알린다.
6. 결과에 가운뎃점(·)이 다시 들어왔는지 `grep -c "·"`로 확인한다.
7. 사용자가 "적용해 줘"라고 하면 원본에 덮어쓴다.

## 옵션

`--chunk 1000`(조각 크기, 표는 보내지 않음), `--jobs`(동시 호출 수, 느리면 1), `--timeout 180`, `--retry 1`, `--style 파일.md`(그 파일의 「## 코덱스에게 전달할…」 절 아래 `- ` 줄만 전달), `--doc "문서 설명"`, `--fresh`(이전 결과 무시).

## 알아 둘 것

- 통과한 조각은 `결과.work/`에 남으므로 중간에 멈춰도 다시 실행하면 이어서 한다.
- `[확인 필요: …]`, `(출처: …)` 표식은 보호되며 개수가 다르면 빨강이다.
- 코덱스를 직접 부를 때는 `< /dev/null`을 붙인다. 입력이 열려 있으면 코덱스가 끝없이 기다린다(polish.py는 이미 처리).
- 바뀐 문단만 떼어 다듬고 다시 합치면 사용량이 크게 준다. Word 문단에 되돌려 넣을 때는 원래 글머리(「- 」, 「①」)를 살린다.
