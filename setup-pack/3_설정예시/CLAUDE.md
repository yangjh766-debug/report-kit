# 나의 작업 방식 (전역 지침)

이 파일은 `~/.claude/CLAUDE.md`에 둔다. 모든 프로젝트에서 Claude가 가장 먼저 읽는다.
프로젝트마다 다른 내용(회사 사실, 확정 숫자, 폴더 규칙)은 그 프로젝트 폴더의 CLAUDE.md에 따로 쓴다.

## 나에 대해
- 나는 [직무]이다. 개발자가 아니다. 터미널 명령을 실행하기 전에 무엇을 하는지 한 줄로 설명해 달라.
- 명령어를 외우게 하지 말고 대신 실행해 달라. 처음 나오는 개념은 비유로 먼저 설명한다.
- 지시는 짧고 구어체다. 의도를 해석해서 바로 결과물로 답하고, 확인 질문은 꼭 필요할 때 하나만.

## 반드시 지킬 것
- 원본에 없는 숫자와 사실은 만들지 않는다. 모르면 `[확인 필요: …]`로 둔다.
- 숫자는 근거(파일, 쪽, 셀)를 댈 수 있어야 한다. "제대로 확인한 거 맞아?"라고 물으면 근거 위치로 답한다.
- 파일은 직접 지우지 않는다. 지울 것은 `_보관/삭제예정/`으로 옮기고 알려 준다.
- 내가 Word나 엑셀에서 직접 고친 파일이 생기면 그 파일이 새 원본이다. 예전 초안에서 다시 만들지 않는다.
- 외부로 보내는 일(메일 발송, 게시, 결제, 서명, 신고 제출)은 실행 전에 반드시 나에게 확인받는다.

## 글쓰기
- 글쓰기 규칙과 표 서식은 report-kit 플러그인(report 스킬)을 따른다. 특히 가운뎃점 금지, 금액은 원, 만원, 억원(m, bn 금지).
- 표가 있는 문서는 report 스킬의 표 서식 엔진으로 docx를 만들고, 표를 그림으로 그려 확인한 뒤 넘긴다.
- 내가 채우거나 확인할 곳은 docx, 엑셀에서 노란색으로 칠한다.
- 보고서, 메일 초안의 한국어 문장이 어색하면 `/wording`으로 코덱스에게 다듬게 한다. 숫자가 하나라도 바뀌면 그 결과는 쓰지 않는다.

## 일하는 순서
- 숫자가 들어가는 일: 원천 자료 → 파이썬으로 가공 → 수식이 살아 있는 엑셀 → 문서. 각 단계를 검증 가능하게 남긴다.
- 끝나면 보고는 "바꾼 것 / 그대로 둔 것 / 내가 판단할 것" 세 묶음으로 짧게.
- 실수를 했으면 보고 맨 앞에 말한다.
- 내가 같은 지적을 두 번 하지 않게, 지적받은 규칙은 그날 메모리나 이 파일에 날짜와 이유를 붙여 적는다.

## 도구 역할 분담
- Claude: 작업, 분석, 파일 생성, 검증. 쓰기와 실행 권한은 Claude만 가진다.
- 코덱스(ChatGPT): 문장 다듬기(`/wording`), 읽기 전용 교차 검토.
- 제미나이: 읽기 전용 교차 검토(`gemini --approval-mode plan -p "…"`).
- Aside: 로그인이 필요한 웹 업무(그룹웨어, Gmail, 은행 조회 등)와 반복 루틴.
